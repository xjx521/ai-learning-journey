## 二、动手实验（约 4 小时，核心）

### 实验 A：认识 ReAct 协议长什么样【示例】★

**概念**：ReAct = **Re**asoning + **Act**ing。它不是新 API，是一种**提示词协议**——让模型按固定格式输出"先思考、再决定调哪个工具"。这一步不写循环，只看懂协议。

【示例】（新概念第一次给示例，详细注释，只看懂长什么样）：

```python
# exp_a_react_single_step.py —— 认识 ReAct 协议
# 我们用 OpenAI 兼容协议调本地 Ollama 的 qwen2.5:7b（Day43 那套写法）
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",  # Ollama 本地不需要真 key，占位即可
)

# 关键：在 system 里告诉模型"可以调用工具"，并规定输出格式（ReAct 协议）
system = """你是能调用工具的助手。需要查资料时，严格按照这个格式输出：

Thought: 你的推理过程
Action: 工具名
Action Input: 工具参数

如果已经知道答案，输出：Final Answer: 最终答案

可用工具：
- get_weather(city)：查询城市天气，参数=城市名，例如 get_weather(北京)
"""

reply = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[
        {"role": "system", "content": system},
        {"role": "user", "content": "北京今天天气怎么样？"},
    ],
    temperature=0,  # 事实型任务压到 0（Day43 实验C 结论）
)
print(reply.choices[0].message.content)
```

跑完观察（填表）：
1. 模型输出的是 `Thought/Action/Action Input` 格式，还是直接给了 `Final Answer`？为什么？（提示：qwen2.5:7b 是 7B 小模型，协议遵守度要看）
2. 如果它没按格式输出，你会怎么提醒它？（提示：few-shot——给一个正确示例，Day46 实验B 结论）

### 实验 B：手写最小 ReAct 循环【骨架】★★★（今天核心）

**概念**：把实验 A 的单步包进 **while 循环**：模型输出 → 解析 Action → **执行工具函数** → 把结果（Observation）拼回对话 → 再问模型 → ……直到 `Final Answer` 或达到 `max_iterations`。这就是 Agent 的最小形态。

【骨架】（关键行留空你填，思路给你）：

```python
# exp_b_react_loop.py —— 手写最小 ReAct Agent
# 三个工具：查天气、加法计算、查公司报销标准（可自己加）
import re
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

def get_weather(city):
    table = {"北京": "晴 28℃", "上海": "雨 24℃", "广州": "多云 30℃"}
    return table.get(city, f"没有 {city} 的天气数据")   # 查不到返回提示而不是报错

def add(a, b):
    return f"{a} + {b} = {a + b}"

def get_policy(keyword):
    policies = {"报销": "出差住宿每晚500元，超标自理", "年假": "满一年5天，满三年10天"}
    return policies.get(keyword, "没有这个政策")

TOOLS = {"get_weather": get_weather, "add": add, "get_policy": get_policy}

SYSTEM = """你是能调用工具的助手。需要工具时输出：
Thought: 你的推理过程
Action: 工具名
Action Input: 工具参数
知道答案时输出：Final Answer: 最终答案
可用工具：get_weather(city) / add(a,b) / get_policy(keyword)"""

def call_llm(messages):
    """调模型，返回回复文本（复用 Day43 写法）"""
    resp = client.chat.completions.create(
        model="qwen2.5:7b", messages=messages, temperature=0,
    )
    return resp.choices[0].message.content

def run_agent(question, max_iterations=5):
    messages = [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": question},
    ]
    for step in range(max_iterations):
        reply = call_llm(messages)
        print(f"[step{step}] {reply}")
        # ① 有最终答案 → 结束循环
        if "Final Answer" in reply:
            return reply
        # ② 正则解析 Action 和 Action Input（模型可能带标点/换行，想想要怎么匹配）
        m = re.search(r"Action:\s*(\w+)\s*Action Input:\s*(\S+)", reply)
        if m is None:
            # ③ 没解析出 Action → 提醒模型按格式来，别直接崩
            messages.append({"role": "assistant", "content": reply})
            messages.append({"role": "user",
                             "content": "请按格式输出 Action 和 Action Input，或给出 Final Answer。"})
            continue
        tool_name, tool_input = m.groups()
        # ④ 执行工具（从 TOOLS 字典里查函数并调用）—— 这一行你填
        # ⑤ 把 Observation 拼回对话（模型无记忆，必须作为新消息发回去）—— 这两行你填
        messages.append({"role": "assistant", "content": reply})
        messages.append({"role": "user",
                         "content": f"Observation: {observation}\n请根据观察结果继续。"})
    return "达到最大迭代次数，强制停止。"

# 跑两个任务：
print("=" * 40)
print(run_agent("北京天气怎么样？"))                      # 单步：查一次天气
print("=" * 40)
print(run_agent("北京天气怎么样？适不适合户外跑步？"))    # 多步：查天气 + 再推理
```

**步骤**：
1. 填空完成 ④⑤（执行工具 + 把 Observation 拼回）
2. 跑上面两个任务，观察循环走了几步、Thought 怎么变化
3. 破坏性：把 `max_iterations` 改成 2，重跑多步任务，看会发生什么

### 实验 C：破坏性对照【提示】★★

**概念**：Agent 系统最容易翻车的三个地方，全试一遍就懂了。

**步骤**（提示级，不给代码）：
1. **工具报错**：把 `get_weather("东京")`（查不到的城市）——它返回的是"没有数据"而不是抛异常。改成让工具**真抛异常**（比如 `raise KeyError`），看循环会怎样：程序崩了？模型会自己重试？生产里该在哪里加 try/except 兜底？（提示：执行工具的 ④ 外面包 try/except）
2. **死循环**：把 `max_iterations` 设成 1，问一个需要多步的问题，观察"强制停止"输出。再想想：**如果 max_iterations 不存在，会怎样？**（提示：模型会一直 Thought/Act，烧 token 不停止）
3. **对比 Day45 Function Calling**：同一个"北京天气"，用 Day45 的 `tools=[...]` 参数（API 结构化保证）vs 今天的文本协议（模型自己拼 Action 文本）——两种"让模型调工具"的机制，**各有什么优缺点**？（提示：FC 格式由 API 保证、解析稳，但只能等模型主动发 tool_calls；ReAct 纯文本任何模型都能跑，但格式靠提示词约束、小模型容易不听话）
