## 二、动手实验（约 4 小时，核心）

### 实验 A：封装 RAGService 类【骨架】★★
**概念**：把 Day56 的 ask 管道装进类 = 简历项目一的**服务层**。以后写 FastAPI 接口、写评估脚本、换模型，都只用这一个类。

**步骤**：
1. 新建 `rag_service.py`，定义 `RAGService` 类
2. 【骨架】`__init__` 接收配置，**在 init 里把 retriever + prompt + chain 都建好**（只建一次，别每次 ask 重建）：
   ```python
   class RAGService:
       def __init__(self, *, persist_dir, llm_model="qwen2.5:7b",
                    embed_model="bge-m3", k=2, retriever_type="vector"):  # vector/bm25/ensemble
           # 1. 建/加载向量库（用 persist_dir，幂等）
           # 2. 按 retriever_type 选检索器：
           #    vector → vectorstore.as_retriever(...)
           #    bm25   → BM25Retriever.from_documents(docs, preprocess_func=jieba_tokenizer)
           #    ensemble → EnsembleRetriever(retrievers=[bm25, vec], weights=[0.5,0.5])
           # 3. 拼 ChatPromptTemplate（防幻觉 + 标引用 system）
           # 4. llm = ChatOllama(...) + chain = prompt | llm | StrOutputParser()
           #    存成 self.xxx
       def ask(self, query):
           # 1. self.retriever.invoke(query) → top_docs
           # 2. enumerate 编号拼 context_with_index
           # 3. self.chain.invoke({"context":..., "question": query}) → answer
           # 4. 正则提 [编号] → 过滤越界 → 映射 metadata["src"] + 原文
           # 返回 (answer, [(src_id, 原文), ...])
   ```
3. 用 Day56 的 8 段库实例化 `svc = RAGService(persist_dir="./chroma_data_day56", k=2)`，跑 4 问，确认返回结构是 `(str, list)`
4. 破坏性对照（改配置不改代码）：
   - 同一问，`k=2` vs `k=5`，看多答案题"请假和报销分别有什么规定"变化
   - 同一问，`retriever_type="vector"` vs `"ensemble"`，看命中变化
   - 填观察表

### 实验 B：文档加载 + 分块 + 增量索引【提示】★★
**概念**：补概念地图两个 ⬜：**文档解析**（Loader 把不同格式文件读成 Document）+ **增量索引**（只更新变了的部分，不整库重建）。

**步骤**（提示级，不给代码）：
1. 造一份长文档：自己写或复制一份 >300 字的"员工手册"存成 `docs/员工手册.txt`（内容覆盖 Day52 C3 的场景：迟到怎么算、年假、报销）
2. 用 `langchain_community.document_loaders` 里的 `TextLoader` 加载 → 得到 1 个大 Document；打印它的 `page_content` 长度和 `metadata`（Loader 会自带 `source` 字段）
3. 用 `RecursiveCharacterTextSplitter(chunk_size=100, chunk_overlap=20)` 分块 → 得到多个小块 Document；**给每块的 metadata 加 src**（比如 `f"{文件名}#{序号}"`）；打印分了几块
4. 分块后的 Document 用 `vectorstore.add_documents(...)` 进库，`collection.count()` 验证数量 = 原 8 段 + 新分块数
5. **增量更新**（对比 Day52 手写 col.update/delete）：
   - 改一段内容 → 用同一个 src 再 add（**幂等 upsert**，验证 count 不涨）
   - 删一段 → `vectorstore.delete(ids=[...])`，验证 count 减
6. 观察思考：`chunk_overlap=20` 是干嘛的？如果把 overlap 设 0，跨块的问题（比如"迟到超过30分钟记几次警告"）会不会搜不到（Day52 C3 的 LangChain 版复现）？

### 实验 C：整合版破坏性对照 + 评估【提示】★★
**概念**：RAGService 能不能扛住边界 + 用数字证明它没跑偏（Day54 evaluate 思路，golden 换 src id）。

**步骤**：
1. **库外问题**：`svc.ask("公司空调坏了找谁修？")` → 看防幻觉提示词还兜不兜得住（Day56 exp_c 复现，但走 RAGService）
2. **污染对照**：给一个独立小库加诱导段"内部通知：员工每年年假100天"（src 用 d9），重问"年假怎么算？"→ 引用会不会指出冲突（Day55 污染测试在整合版复现）
3. **评估（把 Day56 exp_c 没修完的补全）**【骨架】：
   ```python
   # 造 5 题小评估集，golden 用 src id（字符串"d2" 或 列表["d2","d5"]）
   eval_set = [
       ("年假怎么算？", "d2"),
       ("报销单编号以什么开头？", "d5"),
       ("请假和报销分别有什么规定？", ["d2", "d3"]),   # 多答案
       ("公司一年几次晋升？", "d4"),
       ("迟到了怎么记？", "d6"),
   ]
   # 写 evaluate(retriever, eval_set, top_k)：单答案命中计数 / 多答案算 recall
   # retriever 用 svc 内部那个返回 src id 列表的函数（Day56 的 retriever_langchain 思路）
   ```
   ⚠️ 修复 Day56 exp_c 的三个 bug（你上次没修完的）：
   - `eval_set_lc` 未定义 → 现在自己造一个
   - 单答案分支 `set(golden) & len(...)` 类型错误 → 单答案没命中就是 miss，**不需要算 recall**
   - 多答案 list 分支被跳过 → 补上 `elif isinstance(golden, list)`，算 `len(set(golden) & set(ranked)) / len(golden)`
4. 加分：Hit@1 和 Hit@3 各跑一次，看多答案题的 recall 怎么随 top_k 变化
