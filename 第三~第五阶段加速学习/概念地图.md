  1️⃣ 上下文窗口有限（最重要）

  - 是什么：模型一次"看"得下的 token 数是固定的（8k / 32k / 128k…）。窗口之外的文字它完全看不见。
  - 类比：一张桌子。食材（对话历史、文档）放满了，新菜就放不下，要么旧食材被挤下桌（模型忘掉最早的对话），要么新菜放不上
  （报错/截断）。
  - 影响：对话历史越长，模型越"健忘"；文档一大坨塞进去直接超限。
  - 怎么解决：这是 Phase 4 学 RAG
  的核心原因之一——不是把整本书塞给模型，而是只把相关的几段检索出来喂进去，省窗口、还更准。

  2️⃣ 知识截止

  - 是什么：知识来自训练数据，有截止日期。之后发生的事它不知道，但不会承认。
  - 类比：一个失联很久、没看新闻的人。
  - 影响：问"今天北京天气"它会编；问 2026 年新政策它瞎说。
  - 怎么解决：实时信息 → 搜索工具（Phase 5 Agent）；你的私有数据 → RAG。

  3️⃣ 幻觉（你已经注意到了，记得很对）

  - 是什么：模型本质是"预测下一个词"，它不区分真假，只按统计规律续写，所以会一本正经地编。
  - 类比：超自信的销售，不管真假都能讲得头头是道。
  - 影响：知识库问答里，模型会编出文档里根本没有的答案。
  - 怎么解决：Day 55 的"防幻觉 + 引用标注"——提示词里写死"只能根据给它的资料回答，没有就说不知道"，并强制它标出引用来源。

  4️⃣ 随机性

  - 是什么：同一问题输出不一定一样。temperature 越高越"飘"。
  - 类比：掷骰子的厨师，今天少放盐明天多放。
  - 影响：事实型任务（查数据、抽取信息）用高温很危险。
  - 怎么解决：事实/抽取任务 temperature 压到接近 0，创意任务才调高——这就是你实验 C 要亲眼验证的。

  5️⃣ 无记忆（跨调用）

  - 是什么：每次 API 调用都是全新开始，模型不记得上次聊了啥，除非你把历史当 messages 传回去。
  - 类比：每次都失忆的接待员，你得把前面的对话重新念一遍。
  - 影响：多轮对话不管历史，模型就"失忆"。
  - 怎么解决：Day 45 多轮对话——手动维护 messages 列表，这是应用开发者的活。

  6️⃣ 无行动能力

  - 是什么：模型只能输出文字，不能真的查库、发请求、操作文件。
  - 类比：只会出主意的顾问，不动手。
  - 影响："帮我查数据库里上个月的订单"——它做不到。
  - 怎么解决：Function Calling + Agent（Day 46 打底，Phase 5 成体系）。

  7️⃣ 数学/逻辑不可靠（补充）

  - 是什么：它不是计算器，复杂计算会算错，"3.11 和 3.9 谁大"这种也可能翻车。
  - 影响：金融计算、精确统计绝不能靠模型直接算。
  - 怎么解决：用工具（调代码/计算器）——同样是 Function Calling 的用途。
"会续写的统计机器，有 7大边界：窗口/知识截止/幻觉/随机/无记忆/无行动/数学差"
