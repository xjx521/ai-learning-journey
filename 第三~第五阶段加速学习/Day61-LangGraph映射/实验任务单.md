## 二、动手实验（约 3.5 小时，核心）

### 实验 A：认识 StateGraph 最小图【示例】★

**概念**：LangGraph = 把 Agent 流程画成一张图：**State**（状态/共享数据）+ **节点**（一步处理）+ **边**（流程顺序）+ **条件边**（自己决定下一步去哪）。run 时从 START 节点进入，按边走到 END。

【示例】（全新 API 结构，给最小可跑，看懂长什么样）：

```python
# exp_a_graph_basics.py —— 最小 StateGraph
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# ① State：整张图共享的数据（Agent 里就是 messages 对话历史）
class AgentState(TypedDict):
    count: int          # 示例先用一个计数器

# ② 节点：普通 Python 函数，输入 State，返回要更新的字段
def node_1(state: AgentState):
    print("node_1 执行")
    return {"count": state["count"] + 1}   # 返回的 dict 会写回 State

def node_2(state: AgentState):
    print("node_2 执行")
    return {"count": state["count"] + 1}

# ③ 建图：加节点 + 加边（START→node_1→node_2→END）
graph = StateGraph(AgentState)
graph.add_node("n1", node_1)
graph.add_node("n2", node_2)
graph.add_edge(START, "n1")   # 入口
graph.add_edge("n1", "n2")
graph.add_edge("n2", END)     # 出口

# ④ 编译 + 执行（compile 会做校验，invoke 传入初始 State）
app = graph.compile()
result = app.invoke({"count": 0})
print("结果 count =", result["count"])   # 期望 2
```

**步骤**：
1. 跑通上面的最小图，确认 count=2
2. 改动 1：加一个节点 n3 在 n2 之后 → 看 count 变 3（理解"边决定流程"）
3. 改动 2：用 `graph.stream({"count":0})` 逐节点看执行顺序 → 理解"图怎么走"

### 实验 B：把 run_agent 映射成 StateGraph【骨架】★★★（今天的核心）

**概念**：逐行对照（**先看映射表再写，别盲写**）：

| Day60 手写 run_agent                 | LangGraph 对应物                                                     |
| ------------------------------------ | -------------------------------------------------------------------- |
| `for step in range(max_iterations)`  | 图的"边回环"（tools→agent 接回）+ recursion_limit                    |
| `call_llm(messages)`（发消息给模型） | **agent 节点**（调模型，返回带 tool_calls 或 final 的消息）          |
| 正则解析 Action + TOOLS 执行         | **tools 节点**（拿到 tool_calls 逐个执行，结果以 ToolMessage 回写）  |
| `messages.append(Observation)`       | State 里 messages 字段被节点更新（节点 return 的 messages 会并进去） |
| `if "Final Answer" in reply: return` | **条件路由**：有 tool_calls → 走 tools；没有 → 走 END                |
| `max_iterations` 兜底                | recursion_limit（默认 25，超了报 RecursionError）                    |

【骨架】（关键行留空你填）：

```python
# exp_b_react_langgraph.py —— 手写 run_agent 的 LangGraph 版
from typing import TypedDict, Annotated, Literal
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_ollama import ChatOllama
from langchain_core.tools import tool

# ---------- 工具：用 @tool 声明（Day59 已会） ----------
@tool
def get_weather(city: str) -> str:
    """查询城市实时天气"""
    return f"{city} 25°C"   # ① 先简单返回，跑通后再换 Day59 的真实现 —— 你填

TOOLS = [get_weather]

llm = ChatOllama(model="qwen2.5:7b", temperature=0)
llm = llm.bind_tools(TOOLS)   # 让模型能发结构化工具调用（对应 Day60 的"格式约束"）

# ---------- State：messages 是共享的对话历史 ----------
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]   # ② add_messages 归并：新消息自动 append

# ---------- agent 节点：调模型（对应 run_agent 的 call_llm） ----------
def agent_node(state: AgentState):
    result = llm.invoke(state["messages"])   # ③ 传整个历史
    return {"messages": [result]}            # ④ 返回模型消息（add_messages 自动拼进去）

# ---------- tools 节点：执行工具（对应 run_agent 的 TOOLS 执行） ----------
def tools_node(state: AgentState):
    # ⑤ 取最后一条消息的 tool_calls，逐个执行，结果包成 ToolMessage 返回 —— 你填
    pass

# ---------- 条件路由：对应 run_agent 的 Final Answer 判断 ----------
def should_continue(state: AgentState) -> Literal["tools", "END"]:
    # ⑥ 最后一条消息有 tool_calls → 返回 "tools"，否则 → 返回 "END" —— 你填
    pass

# ---------- 建图 ----------
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tools_node)
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_continue, {"tools": "tools", "END": END})
graph.add_edge("tools", "agent")   # ⑦ tools 执行完回到 agent（这就是"循环"！）—— 你填
app = graph.compile()
```

**步骤**：
1. 填 ⑤⑥⑦ 三个空（对照映射表 + 实验 A 的示例代码；工具结果参考 `ToolMessage(content=str(结果), tool_call_id=...)`）
2. 跑"北京天气怎么样？" → 看它会不会 agent→tools→agent→END 走完
3. 打印每一步 State 的 messages 长度 → 理解"工具结果怎么进对话历史"（对应手写版 messages.append）
4. 再跑"3+5 等于几？"（没工具）→ 看条件路由直接走 END（不经过 tools）

### 实验 C：破坏性对照【提示】

1. **checkpointer 跨请求记忆**：`app = graph.compile(checkpointer=MemorySaver())` + `invoke(..., config={"configurable":{"thread_id":"1"}})` → 先问"我叫小明"，再问"我叫什么"→ 看它记得吗？（解决 Day60"刚才记的什么"不记得——State 被持久化，同一个 thread_id 延续）
2. **recursion_limit 防死循环**：故意让工具抛错 / 模型反复调同一工具 → 看 LangGraph 会不会无限循环（对比手写版 max_iterations；LangGraph 默认 recursion_limit=25，超了报 RecursionError 兜底，不会无限烧 token）
3. **create_agent vs 手写图**：拿 Day58 的 create_agent 对比今天手写的 StateGraph——create_agent 内部就是"agent 节点 + 条件路由 + tools 节点"这张图。你能说出它每一步在干嘛吗？（这就是今天最大的收获）

## 三、自测 5 关（晚上自查）

- **能讲**：StateGraph 的 State / 节点 / 边 / 条件路由各是什么？和 run_agent 的对应关系？
- State：图的共享状态存储，Agent 主要存储 messages 消息列表，对应手写的 messages 列表。
节点：执行逻辑的 Python 函数，llm_node 对应 call_llm，tools_node 对应手写工具执行逻辑。
边 add_edge：无条件流转，实现固定顺序执行。
条件路由：读取 state 动态选择下一个节点，实现分支与循环；等价手写 ReAct 里面 if 判断是否调用工具、循环退出逻辑。
手写靠 for 循环实现 Agent 迭代；LangGraph 靠**条件边回跳节点**实现循环。
- **能写**：默写最小 StateGraph 五步（State → 节点函数 → add_node → add_edge → compile/invoke）class AgentState(TypedDict):count: int  def node_1(state: AgentState):print("node_1 执行") return {"count": state["count"] + 1} def node_2(state: AgentState):print("node_2 执行") return {"count": state["count"] + 2} graph=StateGraph(AgentState) graph.add_node("n1",node_1)graph.add_node("n2", node_2)graph.add_edge(START,"n1") graph.add_edge("n1","n2") graph.add_edge("n2",END) app=graph.compile result=app.invoke({"count}:0)print("结果 count =", result["count"])
- **能修**：跑起来报"Expected a dict but got..." → 查什么？（提示：节点必须 return dict 且键是 State 字段）
- 节点必须return dict并且键是state字段 
- **能答 why**：为什么 LangGraph 用"图"而不是 for 循环？（提示：可视化 / 可断点 / 可持久化 / 条件路由灵活，比手写循环工程化）
- 因为图有可视化可断点更好观察内部调用 state可以保证跨对话持久化路由条件灵活
- **能扛边界**：Agent 流程里有"要不要先查库再答"这种分支 → 图怎么表达？（提示：条件边；多 Agent 协作也是图）
