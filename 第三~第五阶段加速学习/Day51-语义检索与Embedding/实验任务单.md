#### Step 1：第一次调 embedding（**新概念 →【示例】**）
只给到"看懂长什么样"的最小版，搞清楚：一句话 → 一个 1024 维的向量。

```python
# 实验 A：第一次把文字变成向量（embedding）
from openai import OpenAI

# Ollama 的本地接口，OpenAI 兼容：地址换成 localhost，api_key 本地不要 key
client = OpenAI(
    base_url="http://127.0.0.1:11434/v1",  # 指向你电脑上正跑着的 Ollama
    api_key="ollama",                       # 占位符，本地服务用不到 key
)

def get_embedding(text: str) -> list:
    """把一段文字变成 1024 个数字的向量"""
    resp = client.embeddings.create(model="bge-m3", input=text)  # 调本地向量模型
    return resp.data[0].embedding          # 向量藏在 data[0].embedding 里

# 认识向量：打印维度 + 前几个数字
vec = get_embedding("我们公司的年假政策")
print("维度:", len(vec))       # 应该是 1024
print("前8个数字:", vec[:8])   # 一串浮点数，人看不懂，机器看

# 手写余弦相似度：两个向量方向的接近程度（新概念，第一次见）
def cosine_similarity(a: list, b: list) -> float:
    """余弦相似度：夹角越小越接近 1。1=同向，0=垂直无关，-1=完全相反"""
    dot = sum(x * y for x, y in zip(a, b))       # 点积：对应位置相乘再求和
    len_a = sum(x * x for x in a) ** 0.5          # 向量 a 的长度（勾股定理推广到 1024 维）
    len_b = sum(x * x for x in b) ** 0.5          # 向量 b 的长度
    return dot / (len_a * len_b)                  # 点积 ÷ 两个长度乘积

# 验证"意思相近的挨得近"
s1 = get_embedding("我们公司入职满一年有5天年假")
s2 = get_embedding("转正满一年能休几天假")
s3 = get_embedding("今天天气不错")
print("年假 vs 年假相关:", round(cosine_similarity(s1, s2), 3))  # 应该偏大（0.6~0.9）
print("年假 vs 天气:   ", round(cosine_similarity(s1, s3), 3))   # 应该偏小（<0.5）
```

**留空记录表格**（先猜再跑）：
| 句子对                         | 我猜相似度 | 实际相似度 | 说明                      |
| ------------------------------ | ---------- | ---------- | ------------------------- |
| 年假句子 vs 年假相关句子       | 高         | 高         | 同义改写也能认出来？      |
| 年假句子 vs 天气句子           | 低         | 低         | 无关就是分低              |
| 天气句子 vs 天气句子（同一句） | 1.0？      | 1.0        | 同一句向量完全一样，cos=1 |

- **观察思考**：同一个意思换了个说法（"年假"→"休几天假"），向量为什么还能"认出来"？（embedding 在训练时见过海量同义改写，学到的是"语义位置"不是"死记字面"）
    embedding训练时见过海量同义改写 学到的是语义位置 把语义相近的向量相近 语义相反远离
### 实验 B：把字符重叠换成向量相似度，retrieve 框架不动（约 1.5h）★★★ 核心

任务：复用 Day50 的 `retrieve`，**只换打分函数**。然后跑对比实验，找出"字符重叠找不到、向量版能找到"的例子。

【骨架】你填空（拿 Day50 的 retrieve 对比着看，变了哪几处）：
```python
knowledge = [
    "薪酬发放：每月15号发放上个月的薪水，遇节假日提前到最近的工作日。",
    "年假政策：入职满一年有5天年假，满三年10天，满五年15天。",
    "报销规则：出差住宿标准每晚500元，餐饮每天100元，超标部分自理。",
    "晋升规则：每年两次晋升窗口，需要主管推荐和答辩评审。",
    "打卡制度：每天早晚各打卡一次，迟到超过30分钟记一次警告。",
    "团建聚餐：每月最后一周有团建活动，公司报销聚餐和场地费用。",
]

def semantic_retrieve(query: str, docs: list, top_k: int = 2) -> list:
    q_vec = get_embedding(query)        # TODO 1: query 的向量只在循环外算一次（为什么？ 因为query只有一条而docs有多条需要在循环里一条条计算然后再排序）
    scored = []
    for doc in docs:
        d_vec = get_embedding(doc)      
        score=cosine_similarity(q_vec,d_vec)# TODO 2: 用 cosine_similarity(q_vec, d_vec) 算分
        scored.append((score,doc))             # 加 (分数, doc) 元组
    scored.sort(key=_lambda x:x[0]___, reverse=True_) # TODO 3: 降序排序
    return [__item[1]_for item in scored[:top_k]_]                       # TODO 4: 取前 top_k 个，只要内容
```
> 思考 TODO 1：如果把 `q_vec = get_embedding(query)` 写进 for 循环里，每次迭代都重算一遍，会怎样？（浪费 + 慢；1000 段文档时差距就大了——这是"能扛边界"的第一课）
    浪费token加慢问题只有一条只需要计算一次即可不需要重复计算
**对比实验（核心）**：下面 4 个问题，分别跑 **Day50 的字符重叠版** 和 **向量版**，各记 top1 + 分数：

| 问题                   | 字符重叠 top1（分数） | 向量版 top1（相似度） | 哪个答得对                             | 为什么                          |
| ---------------------- | --------------------- | --------------------- | -------------------------------------- | ------------------------------- |
| 我入职两年有几天年假？ | 相似度：6             | 相似度：0.802         | 都答对了                               | 字面命中型，两者应该都对        |
| 工资什么时候发？       | 相似度：2             | 相似度：0.765         | 都对了因为有两个发字撞了改一下提问就好 | ← 关键：字符版抓不到"薪酬/薪水" |
| 最近累，想出去放松两天 | 相似度：4             | 相似度：0.502         | 向量版对了                             | ← 关键：字面几乎不重叠          |
| 团建花钱公司报销吗？   | 相似度：6             | 相似度：0.697         | 都对了                                 | 字面命中型，两者应该都对        |

- **观察思考**：字符重叠在"同义改写/大白话"上为什么抓瞎？向量版为什么能命中？——这 1 分就是 embedding 存在的全部意义。Day50 你没做到的，今天做到。
因为字符重叠不能理解语义，只会统计提问和知识库相同字符的数量，输出重合字符最多的文档，所以遇到同义改写就会匹配失败。向量检索会先对文本分词，再通过 Transformer 自注意力机制理解文本含义，生成固定长度的数字向量；模型在训练过程中，让语义相近文本的向量距离靠近，含义相反的向量相互远离，因此可以识别同义改写，完成正确召回
