```python

from langchain_chroma import Chroma
from langchain_ollama import ChatOllama, OllamaEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. 8 段知识库（复用 Day50 的 code_docs）
code_docs = [
    "薪酬发放：每月15号发放上个月的薪水，遇节假日提前到最近的工作日。",
    "年假政策：入职满一年有5天年假，满三年10天，满五年15天。",
    "报销规则：出差住宿标准每晚500元，餐饮每天100元，超标部分自理。",
    "晋升规则：每年两次晋升窗口，需要主管推荐和答辩评审。",
    "打卡制度：每天早晚各打卡一次，迟到超过30分钟记一次警告。",
    "团建聚餐：每月最后一周有团建活动，公司报销聚餐和场地费用。",
    "报销单编号规则：外勤报销单编号以R开头（如R-2024-0015），差旅报销单以T开头，月结报销单以M开头。",
    "服务器机房命名规范：生产环境服务器以PROD开头（如PROD-DB-01），测试环境以TEST开头。",
]

# 2. 字符串 → Document 对象（page_content=正文；metadata 存 src 编号）
docs = [Document(page_content=d, metadata={"src": f"d{i+1}"}) for i, d in enumerate(code_docs)]

# 3. 向量化建库（映射 Day52 的 ChromaDB；用本地 bge-m3；落盘到新目录，别污染旧库）
vectorstore = Chroma.from_documents(
    documents=docs,
    embedding=OllamaEmbeddings(model="bge-m3"),
    ids=[d.metadata["src"] for d in docs],      # 显式给 id，重跑不会无限加重复
    persist_directory="./chroma_data_day56",    # 新版参数名可能是 path，报错看提示
)

# 4. 取检索器（= 输入问题返回前 k 个 Document，映射 Day50 手写 retrieve）
retriever = vectorstore.as_retriever(search_kwargs={"k": 2})

# 5. 拼 prompt（映射 Day50 build_prompt + Day55 防幻觉）
prompt = ChatPromptTemplate.from_messages([
    ("system", "只能根据下面的资料回答，资料里没有就说不知道。\n\n{context}"),
    ("user", "{question}"),
])

# 6. 模型（映射 call_llm；本地 qwen2.5:7b）
llm = ChatOllama(model="qwen2.5:7b")

# 7. LCEL 管道（映射"检索→拼 prompt→生成"整条链）
chain = prompt | llm | StrOutputParser()

# 8. 跑一遍：检索 → 原文拼 context → 进管道
q = "入职两年有几天年假？"
top_docs = retriever.invoke(q)
answer = chain.invoke({"context": "\n".join(d.page_content for d in top_docs), "question": q})
print(answer)
```

### 实验 B：三路检索映射——EnsembleRetriever（【骨架】★★）

概念：Day53 手写的 RRF 融合（`1/(60+rank_bm25) + 1/(60+rank_vector)`），LangChain 里是现成的 **EnsembleRetriever**，默认融合方式就是 RRF。

```python
from langchain_community.retrievers import BM25Retriever
from langchain_classic.retrievers import EnsembleRetriever
import jieba

# ① BM25 侧（映射 Day53 手写 BM25）
# ⚠️ 中文坑：BM25Retriever 默认按空白分词，中文"一个词都不分" → 必须挂分词器
def jieba_tokenizer(text):
    return list(jieba.cut(text))          # jieba.cut("年假政策") → ["年假", "政策"]

bm25 = BM25Retriever.from_documents(
    documents=docs,                        # 复用实验A的 docs（8 个 Document）
    preprocess_func=___jieba_rokenizer___,                # TODO 1: 挂 jieba_tokenizer
)
bm25.k = 2                                 # 默认返回全部文档，要限 top2

# ② 向量侧（复用实验A的 vectorstore）
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 2})

# ③ 融合（映射 Day53 手写 rrf_score，内部就是 1/(60+rank)）
ensemble = EnsembleRetriever(
    retrievers=[bm25, vector_retriever],
    weights=[0.5, 0.5],
)
#公式简化：
# \(score_{final}= w_1\cdot \frac{1}{k+rank_1} \;+\; w_2\cdot\frac{1}{k+rank_2}\)- `weights=[0.5,0.5]`：BM25 和向量检索同等重要。
# - `weights=[0.7,0.3]`：更相信 BM25 关键词，关键词权重更高。
# - `weights=[0.3,0.7]`：更相信向量语义检索

# ④ 跑 Day53 的 4 问
for q in ["入职两年有几天年假？", "工资什么时候发？",
          "最近压力大想请几天假，有政策吗？", "外勤报销单编号以什么开头？"]:
    print(q, "->", [d.page_content for d in ensemble.invoke(q)])
```

- **能讲**：LangChain 五件套各对应手写版的哪个函数？为什么要把手写版映射成框架版？
- 1. **BM25Retriever** → 手写：`bm25_score`打分 + `bm25_retriever`检索函数
2. **vecstore.as_retriever()** → 手写：向量库`col.query(question,k)`（ANN 向量检索，返回 top‑k 文档）

6. **chain（LCEL `|`管道）** → 手写：一整条 RAG 流程：`检索 → build_prompt → call_llm → parse输出`
7.优点：统一接口，组件可插拔快速替换模型，LECL式声明编排简化代码，自带观测、回调、日志，生态工具兼容

- 封装黑盒：底层算法看不到；出 bug 要翻源码；版本升级接口会变（像`EnsembleRetriever`迁移到`langchain‑classic`
  
- **能写**：默写 LCEL 最小 RAG chain（retriever 取 k → 编号拼 context → prompt | llm | parser → invoke）
- docs=[Documents(page_content=d,metadata={"src":f"d{i+1}"})for i ,d in enumerate(code_docs)] vecstore=Choram.from_documents(documents=doc,embedding=OllamaEbeddings(model="bge-m3"),ids=[d.metadata["src"] for d in docs],persist_directory="") retriever=vecstore.as_retriever(search_kwargs={"k":2}) prompt=ChatPromptTemplate.from_messages(("system","...{context}"),("user","{question}")) llm=ChatOllama(model="") chain = prompt|llm|StrOutputParser() top_docs=retriever.invoke(q) answer=chain.invoke({"context":"\n".join(d.page_content for d in top_docs),"question":q}) 
- **能修**：`chain.invoke` 报错 / 检索结果不对，从哪查？（提示：报错看是哪个环节 / retriever 的 k 对不对 / Ollama 服务通不通 / prompt 变量名拼错）
- 1.先看报错信息是哪个环节，再看k是否写对，看ollama服务通不通，看prompt变量名拼错了吗
  
- **能答 why**：手写版能跑，为什么还要映射到 LangChain？（提示：组件可替换 / 生产件齐全（Loader 解析 PDF、评估、日志）/ 和 Phase 5 Agent / LangGraph 打通）
- 优点：统一接口，组件可插拔快速替换模型，LECL式声明编排简化代码，自带观测、回调、日志，生态工具兼容

- **能扛边界**：10 万段生产库，LangChain 的 Chroma retriever 靠什么撑住？（提示：persist_directory 复用已有库不用每次重算 / ANN 索引 / BM25Retriever 全内存遍历 10 万段会怎样 → 换 Elasticsearch / 数据库全文检索）
Chroma 靠两点支撑十万文档：第一 persist_directory 把向量和 HNSW 索引导出到磁盘，启动直接复用，避免每次重算 embedding 重建库；第二 HNSW ANN 近似索引，不暴力遍历全部向量，近似查找候选，保证检索速度。

但 LangChain 自带 BM25Retriever 是内存实现，十万段全部加载内存，查询遍历全部文档，性能很差，生产环境换成 Elasticsearch 这类外部全文检索服务。
