1.LLM职责: 要不要调用工具 调用什么工具完成问题 传入什么参数 发出调用工具请求（json/请求文本）
2.程序层（agent运行框架）：解析LLM发出的工具请求（json/请求文本） 联网，发起检索，访问接口，执行代码，查询向量库

✅注意：模型只是产出调用意图，代码框架来当手脚，进行实际操作
## 面试简答背诵版

大模型本身不具备执行能力，Agent 中的 LLM 仅负责推理并生成工具调用请求；**真实的操作由外层程序解析请求后执行**，执行结果再回传给模型进行下一轮判断。

## 二、动手实验（3-4 小时，核心）

### 实验 A：给模型配一个"加法计算器"（约 1 小时）★
写 `tool_add.py`（从 call_deepseek.py 复制骨架）：
- 这个嵌套结构**别硬背**，照着下面填，注释讲清每层是干嘛的：

```python
tools = [
    {
        "type": "function",                 # 固定写法：这是个"函数工具"
        "function": {
            "name": "add",                  # ← 工具名（模型调用时用这个名字）
            "description": "两个整数相加",   # ← 描述：模型靠它决定"要不要用这个工具"
            "parameters": {                 # 参数说明（JSON Schema 格式）
                "type": "object",
                "properties": {
                    "a": {"type": "integer", "description": "第一个加数"},
                    "b": {"type": "integer", "description": "第二个加数"},
                },
                "required": ["a", "b"],     # 必填参数
            },
        },
    }
]
```

- 问「3 加 5 等于几？」，`create()` 里加 `tools=tools`
- **关键观察**：这次模型**不会直接答 8**，而是返回一个 `tool_calls`。记录它长什么样：
工具调用请求：
  {
    "role": "assistant",
    "content": null,                     ← 没有文字答案！
    "tool_calls": [                      ← 这就是"下单"
      {
        "id": "call_xxx",
        "function": {
          "name": "add",                 ← 想用哪个工具
          "arguments": "{\"a\": 3, \"b\": 5}"   ← 参数，注意是字符串！
        }
      }
    ]
  }

| 观察项                   | 你看到的实际内容       |
| ------------------------ | ---------------------- |
| 想调用哪个工具（name）   | add工具                |
| 参数是什么（arguments）  | "{\"a\": 3, \"b\": 5}" |
| 有没有同时直接给文字答案 | 没有 content是null     |

### 实验 B：你执行工具，把结果喂回去（约 2 小时）★★ 核心
- 拿到 `tool_calls` 后，**你自己**执行计算（`a + b`），把结果作为 **role="tool"** 的消息发回去，模型这才给出最终答案
- 完整流程（记录每一步的 role 和 content）：

| 步骤 | role      | 装的内容                  | 谁产生的               |
| ---- | --------- | ------------------------- | ---------------------- |
| 1    | user      | "3 加 5 等于几？"         | 你                     |
| 2    | assistant | tool_calls: add(a=3, b=5) | 模型                   |
| 3    | tool      | "8"                       | 你（执行工具后塞回去） |
| 4    | assistant | "3 + 5 = 8"               | 模型                   |

> 提示：第 2 步的 assistant 消息**要原样 append 回 messages**（带 tool_calls 的那条），第 3 步的 tool 消息里有个 `tool_call_id` 要跟它对应上——这是最容易踩的坑，卡住了贴报错给我。

### 实验 C：现实场景——天气工具 vs 幻觉对照（约 1 小时）★★★

## 五、给学习助手的自评（交给我时附上）
- 今天最吃力的是哪一关？为什么？
- msg是一个对象 json.loads字符串转字典 .content（模型直接打字回答）和.tool_calls(模型调用工具)互斥
- `response.choices` 是模型备选回答列表，`[0]` 取第一条结果；`.message` 代表模型本轮消息对象。
协议规定：模型两种输出意图互斥。当模型直接回复文字时，`.content` 存放文本；当模型需要调用工具时，所有调用信息存入 `tool_calls`，同时将 `.content` 置为 `None`，二者不会同时生效。
