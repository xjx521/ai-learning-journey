### 1）原始 Encoder+Decoder（翻译）

    输入【源文本】→切割token→独立 Encoder（双向注意力）→向量存储
    Decoder 一边生成译文，一边依靠**交叉注意力回头读取源文本向量**
    两套独立序列：源文本、目标译文

### 2）Decoder-only（GPT 类 LLM）

    只有**一条序列**：`用户提问 + <分隔符> + AI已生成回答`
    不存在 “输入” 和 “输出” 两个独立分支；
    提问本身就是上下文上文，解码器单向注意力向前读取全部提问信息，直接续写下文

### 第二步：快速补充（点到为止，别陷进去）
- OpenAI API 文档的 **Models** 页 → 只看模型列表里的 context window 数字
- OpenAI API 文档的 **Parameters** 页 → 只看 temperature、top_p 两段
top_k指示模型从随机抽样中选择概率最高的k个token eg：coke 40%,aaa 10%,bbb 5%,ccc 1% k=2模型只会从coke和aaa中选择
top_p设置随机抽样中只选择该概率之和不超过p的词（注意：模型概率从高到低排序并开始累加知道小于p为止） eg:coke 40%,aaa 10%,bbb 5%,ccc 1% p=0.5模型从coke和aaa中选择 0.5+0.1
temperature直接影响token概率分布 temperature越大(>1)token概率分布越平均 反之越小（<1） 更紧密遵循模型在训练中最可能序列 （=1）保持模型在训练中默认概率分布 
    eg:苹果：0.75，香蕉：0.20，橘子：0.05
    - T=1：维持 `0.75 / 0.20 / 0.05`，原样采样
    - T=0.3（小于 1）→差距拉大：苹果概率进一步飙升，香蕉、橘子几乎很难抽到
    - T=2（大于 1）→概率被拉平：苹果优势大幅缩小，香蕉、橘子更容易被选中

# 报错调试 401
## 🔍 调试四步走（以后任何报错都这么做）

  第 1 步：认真读报错——错误里全是线索

  看报错最后几行，别被前面一大堆 traceback 吓住：

  openai.AuthenticationError: Error code: 401 -
  {'message': 'Incorrect API key provided...', 'code': 'invalid_api_key'}

  翻译：阿里云服务器说：「你给的钥匙不对」。而且注意，错误消息里甚至直接给了官方文档链接（help.aliyun.com/zh/model-studi
  o/error-code#apikey-error）——这就是「去哪查」的答案：以后任何 API 报错，先看错误消息，官方通常会给文档链接。

  第 2 步：顺着链条找——哪一环断了？

  请求链路是这样的：

  你的 Python → openai 库 → 发到阿里云服务器 → 服务器验钥匙 → 通过? → 处理
                                            ↑
                                      断在这里

  关键证据：这个 401 错误是阿里云服务器返回的（不是本地报错，还带了 request_id）→ 说明请求已经成功到达阿里云，你的
  base_url 地址是对的 ✅。所以问题只可能出在 Key 本身。

  第 3 步：列出 Key 的常见坑

  1. 复制不完整 / 多了空格 / 多了隐藏字符
  2. 重复了 sk- ⚠️ —— 看你的 .env，现在值是 sk-sk-ws-H.EERD...，开头有两个 sk-！正常 Key
  只需要一个。很可能粘贴时把占位符 sk-在这里粘贴你的key 里的 sk- 留下了
  3. 复制成了别的凭证（比如 RAM 的 AccessKey，而不是百炼的 API Key）

  最可能的是第 2 个（sk-sk- 双重前缀）。

  第 4 步：动手修（一次只改一个变量）

  你的操作：
  1. 打开 阿里云百炼控制台 → API-KEY 管理 (https://bailian.console.aliyun.com/)
  2. 点「查看」重新完整复制一次 Key
  3. 回到 .env，把 DASHSCOPE_API_KEY= 后面那一整段全部删掉再粘贴（不要只删中间，这样能确保不再留下旧的 sk-）
  4. 检查：只以 sk- 开头一个、结尾没空格、没换行
