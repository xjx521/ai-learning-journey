## 二、动手实验（3-4 小时，核心）

### 实验 A：认识 token（约 30 分钟）★
- 打开在线 tokenizer（OpenAI 官方页面，或用 tiktoken 库）
- 数这些句子的 token 数，填表：

| 句子 | token 数 |
|------|---------|
| 今天天气真不错，适合出去跑步 | |
| Today is a great day for a run | |
| 你好 | |
| Hello | |

- 观察：**1 个汉字 ≈ ___ 个 token？** 中英文谁更"费"token？
- 思考：假设上下文窗口是 8192 token，上面这样的聊天记录大概能放多少轮？

### 实验 B：注册通义千问 + 拿 API Key（约 1 小时）★ 必须今天完成
- 注册 DashScope（通义千问）→ 实名认证 → 创建 API Key
- 把 Key 存到 `.env` 文件（**绝不能提交 git**，你的 .gitignore 已经有 `.env`）
- 用 Python 调一次模型，打印「你好，介绍一下你自己」

### 实验 C：temperature 破坏性实验（Key 当天下来就做；没下来就明早第一件事做）★★
- 同一句 prompt，分别用 temperature=0 和 1.5，各跑 5 次
- 记录每次输出，填表：

| 次数 | temperature=0 | temperature=1.5 |
|------|--------------|-----------------|
| 1 | | |
| 2 | | |
| 3 | | |
| 4 | | |
| 5 | | |

- 观察：哪个更稳定？哪个更"有创意"？为什么？

## 三、自测 5 关（晚上对着自查）
- **能讲**：一句话向同学解释「上下文窗口满了会怎样」
- **能写**：不查资料写出「temperature 高会怎样、低会怎样」各一条
- **能修**：调 API 报 `401 Unauthorized`，你知道去哪查、怎么改
- **能答 why**：为什么「抽取事实 / 查知识」类任务应该用低 temperature？
- **能扛边界**：输入一次超过上下文窗口，会发生什么？有哪些解决思路？
