- 🚫 跳过：集 11-14 指令微调（那是训练，不是提示）

### 第二步：DeepSeek 官方文档（约 45 分钟，点到为止）
- https://api-docs.deepseek.com/zh-cn/ → 找 **提示库（Prompt Library）** 页面，看 2-3 个官方写好的 prompt 长什么样
- **只看两样**：① 它们怎么把任务说清楚 ② 有没有用示例/格式要求
- 心里装一句话：**模型不"理解"，它只是顺着你给的文字往概率高的方向续写——所以提示词就是给它铺一条好走的路**

### 边读边想的 3 个问题

3. 提示词能 100% 控制输出吗？不能的话，工程上靠什么兜底？

## 二、动手实验（约 3 小时，核心）

> 实验 A/B/C 都从 `call_deepseek.py`（Day43）复制骨架，**只改 messages 里的文字**，不用碰 API 结构。

### 实验 A：指令明确度——模糊 vs 明确（约 1 小时）★

【提示】步骤（不用写新代码，改 prompt 就行）：
1. 复制 Day43 的 call_deepseek.py，把 user 消息换成一条**模糊指令**，比如：
   - 模糊："帮我写个产品介绍"
   - （你自己挑一个想干的事：写个请假条 / 推荐一款手机 / 总结一段话）
2. 跑一遍，记录输出。看模型"自作主张"了哪些东西（自己编了产品名？风格飘？字数失控？）
3. 再把同一条指令改成**明确版**，凑齐四要素：
   - **角色**：你是谁（"你是电商文案"）
   - **任务**：具体要干什么（"为 XX 手机写推荐语"）
   - **约束**：别干什么 / 必须包含什么（"必须包含续航卖点，不要提价格"）
   - **格式**：长度 / 结构（"80 字以内，一段话"）
4. 填对比表：

| 版本 | 指令原文 | 模型输出 | 哪里跑偏 / 哪里贴合 |
| ---- | -------- | -------- | -------------------- |
| 模糊 |          |          |                      |
| 明确 |          |          |                      |

- **观察思考**：明确版只是"多说了几个要求"，模型没变强，但输出为什么"听话"多了？

### 实验 B：Few-shot 少样本——0-shot vs 2-shot（约 1 小时）★★

任务：给一条商品评论，判断情感倾向（正面/负面），**只输出一个词**。

【提示】步骤：
1. 0-shot：直接问 `"这个评论是正面还是负面？『电池两天就没电』"`，跑，记录输出格式
2. 2-shot：在问题前面塞两个示例（放 user 里）：
   - `"『物流超快，包装精美』→ 正面"`
   - `"『客服根本联系不上』→ 负面"`
3. 再问同一条 `"『电池两天就没电』"`，跑，记录输出
4. 填对比表（重点看**格式**是否稳定）：

| 版本 | 你发的内容 | 模型输出 | 格式稳吗（只回一个词？） |
| ---- | ---------- | -------- | ------------------------ |
| 0-shot |           |          |                          |
| 2-shot |           |          |                          |

- **观察思考**：few-shot 里模型学到的是"判断对错"还是"照格式说话"？→ 提示词工程里 few-shot 最大的价值其实是**锁格式**。

### 实验 C：结构化输出——让模型吐能直接用的 JSON（约 1 小时）★★★

任务：从一句话里抽信息，输出 JSON（`{"情感":"正面","关键词":["..."]}`），要求**能直接被 `json.loads` 解析**。

- 方法一（纯自然语言）：`"请把这句话的情感判断输出成JSON，包含情感和关键词两个字段：『电池两天就没电，客服也找不到人』"`
- 方法二（few-shot 模板）：先给一个标准 JSON 示例，再问
- 方法三（**response_format，新参数**）：`create()` 里加 `response_format={"type": "json_object"}`

【示例】方法三是今天唯一的"新 API 结构"，只给到"看懂长什么样"：

```python
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=messages,
    response_format={"type": "json_object"},   # ← 强制模型输出合法 JSON
)
```

> ⚠️ DeepSeek 的坑：用 `json_object` 时，**提示词里必须出现 "json" 这个词**，否则报错。你在 messages 里写"输出JSON"就满足。

【提示】步骤：
1. 三种方法各跑一遍，每次都 `json.loads(输出)` 试一下能不能解析
2. 填对比表：

| 方法 | 模型输出原文 | json.loads 能成功吗 | 失败原因 |
| ---- | ------------ | ------------------- | -------- |
| ①纯自然语言 |              |                     |          |
| ②few-shot模板 |            |                     |          |
| ③response_format |          |                     |          |

- **观察思考**：方法①/② 的输出经常带 ```json 围栏或多余文字——这就是"能修"要练的清洗。真到项目里你会优先选哪种？为什么？
