## 二、动手实验（约 4 小时，核心）

> 三个实验循序渐进：A 造检索器 → B 拼成完整 RAG → C 故意搞坏它看会崩成什么样。

### 实验 A：手写检索器（约 1.5 小时）★★★ 核心

任务：给一个小知识库，手写"字符重叠打分"，找出和问题最相关的段落。

【示例】打分函数（**新概念第一次见**，看懂长什么样就行，别抄进答案里当完整实现）：

```python
def char_overlap_score(query: str, doc: str) -> int:
    """最朴素的'相似度'：问题和文档共用了多少个字。
    字重叠越多 = 越相关。
    先能跑，理解'检索=打分+排序'的本质；Day51 再换成真正的语义相似度。"""
    q_set = set(query)          # 把问题拆成字符集合（自动去重）
    d_set = set(doc)            # 把文档拆成字符集合
    return len(q_set & d_set)   # 两个集合的交集大小 = 重叠字符数
```

### 实验 B：跑通最小 RAG 闭环（约 1.5 小时）★★★ 核心

任务：把实验 A 检索到的段落拼进 prompt，调 DeepSeek 回答，对比"不检索 vs 检索"。

【提示】拼 prompt 的姿势（调 API 你 Day43 就会了，直接抄 `call_deepseek.py` 现成代码）：
- **system 消息**：`"你是一位客服。只能根据下面的资料回答问题，资料里没有的就说'资料里没有'，不要编造。\n\n资料：\n" + "\n".join(top_docs)`
- **user 消息**：用户的问题
- temperature 设 **0**（事实回答，Day43 实验 C 学过）
- 把三个问题各问一次：**不检索直接问** 和 **RAG 检索后问**，各记一行

### 实验 C：破坏性对照——检索坏了会怎样（约 1 小时）★

任务：故意搞坏检索，看回答质量怎么崩。**破坏性实验优先**，这是理解系统边界最快的方式。

【提示】三个破坏：
1. **打分函数改成恒返回 1**：`return 1`（每段同分）→ 检索结果变成"随便取前 2 段"，看回答质量
2. **往知识库里加一段完全无关的**（比如"食堂菜单：周一红烧肉…"）→ 看它会不会被检索出来干扰回答
3. **问一个知识库里根本没有的问题**（如"我们公司股票代码是多少？"）→ 看模型是老实说"资料里没有"还是硬编

**填记录**：

| 破坏方式 | 检索返回了什么 | 回答质量 |
|---------|---------------|---------|
| 打分恒为 1 | | |
| 混入无关段 | | |
| 问库外问题 | | |

- **观察思考**：这三条分别对应 RAG 的哪个环节坏了？（打分坏=检索环节；无关段混入=增强环节；库外问题=生成环节——防幻觉提示词写没写对）
