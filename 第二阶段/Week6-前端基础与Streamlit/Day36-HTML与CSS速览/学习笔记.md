## 一、为什么 AI 应用开发者需要懂一点前端？

先想一个问题：你辛苦训练/调用的 AI 模型，怎么让用户用上？

- 模型在 Python 里算出一个结果 → **用户看不到**。
- 用户需要一个**界面**：一个输入框，一个按钮，一个结果展示区。

这个「界面」就是**前端**。AI 应用 = 前端界面 + 后端接口 + AI 能力（模型/API）。

### 但你不必成为前端工程师

**Streamlit 这样的工具，专门为「不会前端的 Python 开发者」设计**：你用纯 Python 写界面，它自动生成网页。所以本周你几乎不需要手写 HTML。

但你还是需要了解基础，因为：
1. **Streamlit 底层就是 HTML 网页**——懂了底层，用起来不慌。
2. 面试时能聊清楚「你会不会前端 / 前端和后端怎么配合」。
3. 以后要做**自定义程度高**的界面（或给简历加分的复杂项目）时，知道该补什么。

**一句话总结**：前端 = 用户看到的界面。AI 应用开发者要「懂但不必精」，Streamlit 就是你的免考金牌。

## 二、前端三大件：骨架、皮肤、肌肉

一个网页由三种技术组成，用**人**来类比最直观：

| 技术 | 类比 | 职责 | 后缀 |
|------|------|------|------|
| **HTML** | 骨架 | 内容是**什么**（标题、段落、按钮、图片） | `.html` |
| **CSS** | 皮肤/衣服 | 长**什么样**（颜色、大小、位置、间距） | `.css` |
| **JavaScript** | 肌肉/大脑 | 能做**什么**（点击事件、发请求、动态变化） | `.js` |

习惯说法：
- **HTML** = HyperText Markup Language，超文本**标记**语言。它不复杂，就是用「标签」把内容包起来。
- **CSS** = Cascading Style Sheets，层叠**样式**表。给 HTML 元素「化妆」。
- **JS** = JavaScript，真正的编程语言。处理交互和逻辑 —— 本周你的 JS 角色由 **Streamlit 背后的 Python** 代替，所以 JS 暂时不用深学。

记忆：**HTML 负责内容，CSS 负责好看，JS 负责动作。**

## 三、看懂一个 HTML 页面的结构

HTML 由一层套一层的「标签」组成。一个最小页面长这样：

```html
<!DOCTYPE html>              <!-- 告诉浏览器：这是 HTML5 文档 -->
<html>                       <!-- 最外层根标签 -->
  <head>                     <!-- 头部：不是给用户看的，是给浏览器看的 -->
    <meta charset="UTF-8">  <!-- 告诉浏览器用中文编码 -->
    <title>我的页面</title>  <!-- 浏览器标签页上显示的名字 -->
  </head>
  <body>                     <!-- 身体：用户看到的所有内容都在这 -->
    <h1>你好，世界</h1>      <!-- h1 一级大标题 -->
    <p>这是一个段落。</p>    <!-- p 段落 -->
    <a href="https://www.baidu.com">点我</a>  <!-- a 超链接 -->
    <img src="cat.jpg" alt="猫">  <!-- img 图片 -->
  </body>
</html>
```

### 常见标签速查表（看懂即可，不用背）

| 标签 | 含义 | 例子 |
|------|------|------|
| `<h1>`~`<h6>` | 标题，1 最大 6 最小 | `<h1>大标题</h1>` |
| `<p>` | 段落 | `<p>一段文字</p>` |
| `<a>` | 超链接，`href` 指去哪 | `<a href="网址">文本</a>` |
| `<img>` | 图片，`src` 指图片路径 | `<img src="a.png">` |
| `<ul>` / `<li>` | 无序列表 / 列表项 | `<ul><li>第一项</li></ul>` |
| `<button>` | 按钮 | `<button>点我</button>` |
| `<input>` | 输入框 | `<input type="text">` |
| `<div>` | 块级容器（装东西的盒子） | `<div>...</div>` |
| `<form>` | 表单（一组输入+提交） | `<form>...</form>` |

### 标签的两个核心概念

1. **标签几乎都是成对的**：`<p>内容</p>`，开始标签 + 结束标签（结束标签有 `/`）。
2. **标签可以嵌套**：盒子套盒子，就像俄罗斯套娃。

```html
<div>
  <h1>标题</h1>
  <p>内容</p>
</div>
```

### 破坏性理解实验
> 把这个 HTML 存成 `test.html`，用浏览器打开，然后试着：
> - 把 `<h1>` 改成 `<h3>` 再刷新 → 字变小了（h 数字越大字越小）
> - 删掉 `<p>` 的结束标签 `</p>` → 浏览器通常还是显示，但结构变乱（浏览器很宽容）
> - `<img>` 的 `src` 写一个不存在的图片 → 显示一个破图/占位（不报错）

## 四、CSS：给页面化妆

CSS 负责「长什么样」。它的基本写法是：**选中谁 → 设置什么属性 → 设置成什么值**。

```css
h1 {                /* 选中所有 h1 标题 */
  color: red;       /* 颜色变红 */
  font-size: 32px;  /* 字号 32 像素 */
}
```

CSS 的三种写法：
1. **内联**：直接写在标签里（不推荐，难维护）
2. **内部**：写在 `<style>` 标签里（现在用这个，简单）
3. **外部**：写在独立 `.css` 文件里（工程上最推荐，但对你暂不必须）

用「类（class）」选中是常见做法 —— 给元素起个名字，再用 CSS 用这个名字化妆：

```html
<p class="danger">这是危险提示</p>

<style>
.danger {          /* .类名 前面有个点 */
  color: red;
  font-weight: bold;  /* 加粗 */
}
</style>
```

## 五、前端框架概念（Day 36 的重点概念之一）

### 什么是前端框架？

网页内容一变多，用「原生 HTML 手动改 DOM」会非常痛苦（要和浏览器底层打交道）。于是出现了**前端框架**——给你提供现成的组件、状态管理、写法，让你"用更省事的方式做界面"。

常见前端框架：
- **React**（最流行，Meta 出品，大厂用得多）
- **Vue**（中文社区友好，上手相对简单）
- **Svelte、Angular** 等

### 框架到底解决了什么？（用写清单类比）

| 传统方式 | 框架方式 |
|----------|----------|
| 每次变动都要手动找到那个元素、改它 | 你只声明「这个列表是啥」，变了自己更新 |
| 数据和界面没关联 | 数据一变，界面自动跟着变 |
| 代码一大就乱 | 拆成一个个「组件」复用 |

类比：传统前端像「一块板上手写所有内容，改一处要手动全擦」；框架像「Excel——你改单元格（数据），图表（界面）自动刷新」。

### 一个重要结论

**Streamlit 在扮演「迷你前端框架」的角色！** 你在 Python 里写：
```python
st.title("标题")         # 即一个界面元素
```
Streamlit 后端帮你生成 HTML/CSS/JS，替你干掉了「手动写前端」的所有活。

所以今天学的概念，会让你真正**理解为什么 Streamlit 好用**：
- 你不用手动管 HTML 结构 → Streamlit 帮你生成
- 你不用手动写 CSS → 它自带主题
- 你不用写 JS 处理交互 → 每次交互它自动重跑脚本

## 六、前后端如何配合（建立整体观）

一个完整的 Web 应用：

```
浏览器（前端）  ——HTTP 请求（携带数据/按钮点击）-->  服务器（后端 API）
    ↑                                                  |
    └--------------- HTTP 响应（返回 JSON 数据）---------┘
```

- **前端**负责：展示、收集用户输入、发请求、渲染结果。
- **后端**负责：处理业务逻辑、读写数据库、调用 AI。
- 两者通过 **HTTP 接口（你已学的 FastAPI）** 通信。

你在 Week 4 学的 FastAPI 就是「后端」；明天 Day 37 的 Streamlit 就是「前端」。把它们用 HTTP 连起来，就是完整应用 —— 这正是 Day 39-40 综合项目要做的事。
