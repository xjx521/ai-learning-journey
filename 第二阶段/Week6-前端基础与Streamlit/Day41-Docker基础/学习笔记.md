## 一、为什么要用 Docker？（先解决"为什么"）

你遇到过"我的电脑上能跑，换台电脑就报错"吗？

- 你本地装好了 Python、FastAPI、SQLAlchemy、数据库……
- 换台电脑（或部署到服务器），版本不一样，各种依赖缺失，跑不起来。

**Docker 解决这个问题**：把「你的应用 + 它需要的所有环境」打包成一个**标准化的盒子（镜像）**，在任何电脑上都能原样运行。

> 类比：搬家。你把"家具 + 装修 + 水电"打包进一个**标准集装箱**，运到任何地方打开就能住，不用重新装修。

## 二、核心概念：镜像 vs 容器

| 概念 | 类比 | 说明 |
|------|------|------|
| **镜像（Image）** | 一个**模板 / 安装包** | 打包好的应用，只读，不能改 |
| **容器（Container）** | 根据模板**运行起来的实例** | 镜像跑起来就是容器，可以启动/停止/删除 |

> 类比：镜像是"披萨胚子的模具"，容器是"用模具做出来的一个披萨"。一个模具能做很多个披萨，每次做的都是独立的。

- 一个镜像 → 可以跑出**多个容器**（互不影响）
- 容器删了，镜像还在（还能再跑）

### 和虚拟机（VM）的区别

| | 虚拟机 | Docker 容器 |
|--|--------|------------|
| 装了什么 | 完整操作系统（重） | 只装应用 + 依赖（轻） |
| 启动速度 | 慢（分钟级） | 快（秒级） |
| 内存占用 | 大 | 小 |

## 三、Dockerfile：怎么"打包"你的应用

**Dockerfile** 是一个文本文件，告诉 Docker "怎么一步步把应用打包成镜像"。它是**从上到下**执行的指令列表。

### 一个把 FastAPI 应用容器化的 Dockerfile

```dockerfile
# 从哪个基础镜像开始（这里用 python 3.11 作为基础）
FROM python:3.11-slim

# 设置工作目录（容器里进入这个目录）
WORKDIR /app

# 把本机 requirements.txt 复制进容器
COPY requirements.txt .

# 在容器里安装依赖
RUN pip install -r requirements.txt

# 把本机当前目录的所有文件复制进容器
COPY . .

# 声明容器对外暴露的端口（只是声明，不实际映射）
EXPOSE 8000

# 容器启动时执行的命令
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### Dockerfile 核心指令表

| 指令 | 作用 | 例子 |
|------|------|------|
| `FROM` | 指定基础镜像（必须第一行） | `FROM python:3.11-slim` |
| `WORKDIR` | 设置工作目录 | `WORKDIR /app` |
| `COPY` | 把本机文件复制进容器 | `COPY . /app` |
| `RUN` | 在容器里执行命令（构建时） | `RUN pip install -r requirements.txt` |
| `EXPOSE` | 声明端口（说明用） | `EXPOSE 8000` |
| `CMD` | 容器启动时执行的命令 | `CMD ["uvicorn", "main:app", ...]` |

> 记住顺序套路：**FROM → WORKDIR → COPY requirements → RUN install → COPY 代码 → EXPOSE → CMD**

## 四、docker build 和 docker run（核心命令）

### 构建镜像 `docker build`

```bash
# 在 Dockerfile 所在目录执行
docker build -t my-app .
```

- `-t my-app`：给镜像起个名字（tag）
- `.`：用当前目录下的 Dockerfile 来构建

### 运行容器 `docker run`

```bash
# 用镜像 my-app 跑一个容器
docker run -p 8000:8000 my-app
```

- `-p 8000:8000`：**端口映射**。左边是"本机端口"，右边是"容器端口"。
  - 浏览器访问 `localhost:8000` → 转发到容器里的 `8000`
- `-d`：后台运行（加 `-d` 就不占终端）
- `--name my-container`：给容器起名字

### 管理容器

| 命令 | 作用 |
|------|------|
| `docker ps` | 列出正在运行的容器 |
| `docker ps -a` | 列出所有容器（含已停止） |
| `docker logs <容器名>` | 查看容器日志 |
| `docker exec -it <容器名> bash` | 进入容器内部执行命令 |
| `docker stop <容器名>` | 停止容器 |
| `docker rm <容器名>` | 删除容器 |
| `docker images` | 列出本机镜像 |
| `docker rmi <镜像名>` | 删除镜像 |

## 五、docker-compose：一键启动多个服务

当你的应用有**多个服务**（比如后端 + 数据库 + 前端）时，一个个 `docker run` 太麻烦。用 **docker-compose** 用一个文件描述所有服务，一键启动。

### docker-compose.yml 示例

```yaml
version: "3.8"

services:
  backend:                    # 服务名
    build: ./backend          # 用 backend 目录下的 Dockerfile 构建
    ports:
      - "8000:8000"           # 端口映射
    environment:
      - DATABASE_URL=sqlite:///./app.db    # 环境变量
    volumes:
      - ./backend:/app        # 挂载（选做）

  db:                          # 另一个服务
    image: postgres:15         # 直接用现成的镜像
    environment:
      - POSTGRES_PASSWORD=secret
    ports:
      - "5432:5432"
```

### docker-compose 常用命令

```bash
docker-compose up        # 启动所有服务（-d 后台）
docker-compose down      # 停止并移除
docker-compose ps        # 查看状态
docker-compose logs      # 查看日志
```

> 写法要点：`services:` 下每个缩进两层的是一个服务；每个服务写 `build` 或 `image`、`ports`、`environment` 等。

## 六、完整示例：容器化你的 FastAPI 应用

假设你有个 `main.py`（FastAPI 应用）和 `requirements.txt`：

**requirements.txt**
```
fastapi
uvicorn
sqlalchemy
```

**Dockerfile**
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**构建并运行**
```bash
docker build -t my-api .      # 构建镜像
docker run -p 8000:8000 my-api  # 运行容器
# 浏览器访问 localhost:8000/docs
```

> 注意：FastAPI 里 `--host 0.0.0.0` 很重要——它让容器外也能访问（默认 127.0.0.1 只允许容器内部访问）。
