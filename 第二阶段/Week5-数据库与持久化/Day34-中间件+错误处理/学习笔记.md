## 一、Middleware（中间件）是什么？

类比理解：HTTP 请求经过一个"安检通道"——每个安检员（中间件）检查一个方面，合格就放行给下一个。

```
浏览器请求 → [CORS中间件] → [日志中间件] → [认证中间件] → 你的路由函数
                          ↑            ↑              ↑
                    跨域检查       记录日志      Bearer验证
```

### 请求流程全景图

```
1. 浏览器发出请求
2. ↓ 进入第一个中间件（最外层）
3.   ↓ 进入第二个中间件
4.     ↓ ...继续往下
5.       到达你的路由函数（真正干活的代码）
6.     ↑ 响应往回走，经过第二个中间件
7.   ↑ 响应往回走，经过第一个中间件
8. ↑ 回到浏览器
```

注意：**响应是倒着走过中间件的**，就像穿脱衣服一样——先穿的内衣（第一个中间件），最后脱的也是内衣。

### FastAPI 中注册中间件的方式

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,                     # 哪个中间件类
    allow_origins=["http://localhost:3000"],  # 允许的源
    allow_credentials=True,             # 允许携带 Cookie
    allow_methods=["*"],                # 允许的方法（GET/POST...）
    allow_headers=["*"],                # 允许的请求头
)
```

`add_middleware()` 的参数顺序就是中间件在请求中的**进入顺序**。

## 二、CORS 跨域资源共享详解

### 什么是跨域？

浏览器的**同源策略**（Same-Origin Policy）：只有当协议 + 域名 + 端口三者都相同时，才算"同源"，才能互相访问。

| 场景           | API地址            | 前端地址            | 是否跨域 | 原因     |
| -------------- | ------------------ | ------------------- | -------- | -------- |
| 本地开发       | localhost:8000     | localhost:3000      | 是       | 端口不同 |
| 同域名不同子域 | api.example.com    | www.example.com     | 是       | 域名不同 |
| http vs https  | http://example.com | https://example.com | 是       | 协议不同 |
| 同域同端口     | localhost:8000     | localhost:8000      | 否       | 完全相同 |

### CORS 是怎么工作的？

当你从 frontend:3000 请求 api:8000 时，浏览器会先发一个 **OPTIONS 预检请求**：

```
浏览器 → OPTIONS /api/users (Access-Control-Request-Method: POST)
API    → 200 OK (Access-Control-Allow-Origin: http://localhost:3000)
浏览器 → 哦，服务器允许我，现在发真正的 POST 请求
API    → 201 Created ✅
```

如果没有 CORS 配置，API 的响应里就没有 `Access-Control-Allow-Origin` 头，浏览器就会拦截响应并报错：

```
Blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

### CORS 响应头一览

| 响应头                           | 作用                   | 示例                              |
| -------------------------------- | ---------------------- | --------------------------------- |
| Access-Control-Allow-Origin      | 允许哪些来源访问       | `http://localhost:3000` 或 `*`    |
| Access-Control-Allow-Methods     | 允许哪些 HTTP 方法     | `GET, POST, PUT, DELETE, OPTIONS` |
| Access-Control-Allow-Headers     | 允许哪些请求头         | `Content-Type, Authorization`     |
| Access-Control-Max-Age           | 预检结果缓存多久（秒） | `86400` = 24小时                  |
| Access-Control-Allow-Credentials | 是否允许带 Cookie      | `true`                            |

### 常用配置方式

```python
# 方式1：宽松模式（仅用于开发）
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],                  # 允许所有来源
    allow_methods=["*"],
    allow_headers=["*"],
)

# 方式2：严格模式（推荐生产环境使用）
import os
from dotenv import load_dotenv
load_dotenv()

allowed = os.getenv("ALLOWED_ORIGINS", "").split(",")
# "http://localhost:3000,http://localhost:8080" → ["http://localhost:3000", "http://localhost:8080"]

app.add_middleware(
    CORSMiddleware,
    allow_origins=allowed,
    allow_credentials=True,               # 允许带 Cookie
    allow_methods=["GET", "POST", "PUT", "DELETE", "PATCH"],
    allow_headers=["Authorization", "Content-Type"],
)
```

### ⚠️ CORS 常见陷阱

**陷阱1：allow_origins=["*"] 和 allow_credentials=True 不能同时存在！**

```python
# ❌ 这会直接抛出 ValueError！
CORSMiddleware(
    allow_origins=["*"],
    allow_credentials=True,   # 💥 ValueError!
)
```

为什么？因为 `*` 意味着"任何网站都能访问我"，而 `credentials=True` 意味着"允许携带用户的 Cookie/Token"。这两个一起等于告诉浏览器："随便哪个网站的任何人，都可以用你的身份访问我的 API"——这是严重的安全漏洞。

**陷阱2：前端需要手动设置 withCredentials**

```javascript
// 即使后端配了 allow_credentials=True，前端也要告诉浏览器带凭证：
fetch("http://localhost:8000/api/users", {
    credentials: "include"   // ← 这行不能少！
})
```

**陷阱3：只加中间件不够，路由也要返回正确的状态码**

OPTIONS 预检请求由 FastAPI 自动处理（返回 200），但如果你的自定义中间件拦截了它，记得放行。

## 三、自定义中间件：日志中间件

FastAPI 内置了 CORS 中间件，但其他功能需要自己写。最实用的就是**日志中间件**。

```python
import time
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request

class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        start_time = time.time()                  # ① 记录开始时间

        response = await call_next(request)       # ② 调用后续中间件和路由

        duration = time.time() - start_time       # ③ 计算耗时

        print(f"[{request.method}] {request.url.path} "
              f"— {response.status_code} — {duration:.3f}s")

        return response                           # ④ 把响应传回去

app.add_middleware(LoggingMiddleware)
```

执行效果：
```
[GET] /todos — 200 — 0.012s
[POST] /todos — 201 — 0.015s
[GET] /todos/999 — 404 — 0.003s
[POST] /todos — 422 — 0.001s
```

**中间件的三个关键方法：**
| 方法                            | 用途                         | 适用场景             |
| ------------------------------- | ---------------------------- | -------------------- |
| `BaseHTTPMiddleware.dispatch()` | 通用中间件，每次请求调用一次 | 日志、计时、简单修改 |
| `CORSMiddleware`                | 专用 CORS 中间件             | 跨域处理             |
| 自定义类继承 MiddlewareStack    | 异步上下文管理器             | 复杂逻辑             |

## 四、认证中间件（进阶）

实际项目中，大多数接口都需要登录才能访问。可以用中间件统一做认证：

```python
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import JSONResponse

# 不需要认证的白名单路径
PUBLIC_PATHS = ["/", "/docs", "/openapi.json", "/favicon.ico", "/login"]

class AuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 白名单直接放行
        if request.url.path in PUBLIC_PATHS:
            return await call_next(request)

        # 检查 Authorization 头
        token = request.headers.get("Authorization", "")
        if not token.startswith("Bearer "):
            return JSONResponse(
                status_code=401,
                content={"message": "未提供认证令牌"}
            )

        # 验证 token（简化版）
        token_value = token[7:]  # 去掉 "Bearer " 前缀
        if token_value != "my_secret_token":
            return JSONResponse(
                status_code=403,
                content={"message": "令牌无效"}
            )

        # 通过认证，放行
        return await call_next(request)

app.add_middleware(AuthMiddleware)
```

测试：
```bash
curl http://localhost:8000/todos          # 401 未提供认证令牌
curl -H "Authorization: Bearer wrong" http://localhost:8000/todos  # 403 令牌无效
curl -H "Authorization: Bearer my_secret_token" http://localhost:8000/todos  # 200 成功
```

## 五、错误处理：全局异常捕获

### 为什么需要统一错误处理？

FastAPI 默认的错误格式是这样的：
```json
{"detail": "Not Found"}
```

但更好的做法是返回统一的格式，让前端容易解析：
```json
{
    "success": false,
    "error": {
        "code": 404,
        "message": "待办事项不存在",
        "path": "/todos/999"
    }
}
```

### 全局异常处理器

```python
from fastapi import Request, HTTPException
from fastapi.responses import JSONResponse

@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    """捕获所有未被处理的异常"""
    return JSONResponse(
        status_code=500,
        content={
            "success": False,
            "error": {
                "code": 500,
                "message": "服务器内部错误",
                "detail": str(exc),           # 生产环境不要暴露 detail！
            }
        }
    )
```

### 针对不同异常类型的处理器

你可以为不同类型的异常注册不同的处理器：

```python
from fastapi import Request, HTTPException, RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import ValidationError

# 1. 参数验证错误（比如类型不对、字段缺失）→ 422
@app.exception_handler(RequestValidationError)
async def validation_error_handler(request: Request, exc: RequestValidationError):
    errors = []
    for err in exc.errors():
        errors.append({
            "field": ".".join(str(loc) for loc in err["loc"]),
            "message": err["msg"],
        })
    return JSONResponse(
        status_code=422,
        content={
            "success": False,
            "error": {
                "code": 422,
                "message": "请求数据验证失败",
                "details": errors,
            }
        }
    )

# 2. HTTP 自定义错误（比如 raise HTTPException(404)）→ 4xx
@app.exception_handler(HTTPException)
async def http_error_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "success": False,
            "error": {
                "code": exc.status_code,
                "message": exc.detail,
                "path": str(request.url.path),
            }
        }
    )

# 3. 其他所有未捕获的异常 → 500
@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    return JSONResponse(
        status_code=500,
        content={
            "success": False,
            "error": {
                "code": 500,
                "message": "服务器内部错误",
                "detail": str(exc),
            }
        }
    )
```

**异常处理器的优先级：** 越具体的处理器优先级越高。`RequestValidationError` > `HTTPException` > `Exception`（兜底）。

### 统一响应格式的好处

```json
// ✅ 统一格式，前端可以直接这样写：
{
    "success": true,
    "data": {
        "id": 1,
        "title": "学习 FastAPI",
        "completed": false
    }
}

// ❌ 或者出错时：
{
    "success": false,
    "error": {
        "code": 404,
        "message": "待办事项不存在"
    }
}

// 前端代码：
const res = await fetch("/todos/999");
if (!res.ok) {
    const json = await res.json();
    console.error(json.error.message);  // "待办事项不存在"
}
```

## 六、环境变量管理

### 什么是环境变量？

环境变量是操作系统或配置文件中的键值对，程序启动时读取它们来改变行为，而不需要改代码。

```
同一份代码，不同的 .env 文件 = 不同的运行环境
```

### python-dotenv 基础用法

```bash
pip install python-dotenv
```

```python
from dotenv import load_dotenv
import os

# 加载 .env 文件中的所有变量到 os.environ
load_dotenv()

# 获取变量，括号里是默认值（找不到时用）
DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./todos.db")
SECRET_KEY = os.getenv("SECRET_KEY")        # 没有默认值，找不到就是 None
DEBUG = os.getenv("DEBUG", "false").lower() == "true"
# ".env" 里的 DEBUG=true → .lower() 变成 "true" → 和 "true" 比较 → True
PORT = int(os.getenv("PORT", "8000"))       # 转成整数
```

### .env 文件格式

```bash
# 注释用 # 开头
DATABASE_URL=sqlite:///./todos.db
SECRET_KEY=abc123supersecret
DEBUG=true
PORT=8000
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:8080
```

**注意事项：**
- `.env` 文件里**不要引号**（除非值本身就包含空格需要用引号包裹）
- 值里有空格时要引号：`GREETING="Hello World"`
- 空的值：`EMPTY_VAR=` → `os.getenv("EMPTY_VAR")` 返回空字符串 `""`

### 多环境配置

```
config/
├── .env.development    # 开发环境
├── .env.production     # 生产环境
└── .env.testing        # 测试环境
```

```python
# .env.development
DATABASE_URL=sqlite:///./dev_todos.db
DEBUG=true
LOG_LEVEL=debug

# .env.production
DATABASE_URL=postgresql://user:pass@db.server.com/prod_db
DEBUG=false
LOG_LEVEL=warning
```

```python
import os
env = os.getenv("APP_ENV", "development")  # 默认开发环境
load_dotenv(f".env.{env}")                 # 加载对应环境的配置
```

### 为什么一定要用环境变量？

1. **敏感信息不入库**：密钥、密码、API Token 永远不要硬编码在代码里提交到 Git
2. **不同环境不同配置**：开发用 SQLite，生产用 PostgreSQL，改个 .env 就行
3. **团队协作友好**：每人有自己的 .env（`.gitignore` 排除），不会冲突
4. **部署方便**：云平台的密钥管理服务可以直接注入环境变量

⚠️ **记住：`.env` 文件一定要加到 `.gitignore` 里！**

```bash
# .gitignore
.env
.env.*
__pycache__/
*.pyc
```

## 七、完整综合示例

把前面学的所有东西合在一起：

```python
from fastapi import FastAPI, Request, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import JSONResponse
from dotenv import load_dotenv
import os

# ── 1. 加载环境变量 ──
load_dotenv()
DEBUG = os.getenv("DEBUG", "false").lower() == "true"
ALLOWED_ORIGINS = os.getenv("ALLOWED_ORIGINS", "").split(",")
SECRET_KEY = os.getenv("SECRET_KEY", "")

# ── 2. 创建 FastAPI 应用 ──
app = FastAPI(title="Todo API", version="1.0.0")

# ── 3. CORS 中间件 ──
app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# ── 4. 日志中间件 ──
import time
from starlette.middleware.base import BaseHTTPMiddleware

class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        start = time.time()
        response = await call_next(request)
        elapsed = time.time() - start
        print(f"[{request.method}] {request.url.path} — {response.status_code} — {elapsed:.3f}s")
        return response

app.add_middleware(LoggingMiddleware)

# ── 5. 统一错误处理 ──
@app.exception_handler(HTTPException)
async def http_error_handler(request: Request, exc: HTTPException):
    return JSONResponse(status_code=exc.status_code, content={
        "success": False,
        "error": {"code": exc.status_code, "message": exc.detail, "path": str(request.url.path)}
    })

# ── 6. 路由 ──
todos = {}

@app.get("/todos")
def list_todos():
    return {"success": True, "data": list(todos.values())}

@app.post("/todos", status_code=201)
def create_todo(title: str):
    todo_id = len(todos) + 1
    todos[todo_id] = {"id": todo_id, "title": title, "completed": False}
    return {"success": True, "data": todos[todo_id]}

@app.get("/todos/{todo_id}")
def get_todo(todo_id: int):
    todo = todos.get(todo_id)
    if not todo:
        raise HTTPException(status_code=404, detail="待办事项不存在")
    return {"success": True, "data": todo}
```
