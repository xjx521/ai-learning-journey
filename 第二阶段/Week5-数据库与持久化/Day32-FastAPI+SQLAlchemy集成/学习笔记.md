## 一、为什么需要依赖注入？

想象一个场景：每个请求都需要一个独立的数据库 Session。

**不好的写法**——每个路由函数都自己创建和关闭：

```python
@app.get("/todos")
def list_todos():
    db = SessionLocal()              # ← 每个路由都要写一次
    todos = db.query(Todo).all()
    db.close()                       # ← 还要记得关掉！忘了就泄漏
    return todos

@app.post("/todos")
def create_todo(todo: TodoCreate):   # ← 又要写一遍！
    db = SessionLocal()              # 重复！重复！重复！
    new_todo = Todo(**todo.dict())
    db.add(new_todo)
    db.commit()
    db.refresh(new_todo)
    db.close()
    return new_todo
```

这样写有三个问题：
1. **代码重复**——每个路由都要写 `SessionLocal()` 和 `db.close()`
2. **容易忘记 close()**——如果路由中间报错了（比如抛出异常），`db.close()` 永远不会被执行，连接会泄漏
3. **不好维护**——如果要换数据库（SQLite → PostgreSQL），每个路由都要改

**Depends() = 自动管理生命周期的神器**：你只需要声明"我需要 db"，FastAPI 负责帮你创建、传递、清理。

类比理解：
```
就像住酒店——
手动管理 = 自己带水自己烧自己喝（每次都做一样的事）
Depends() = 打开水龙头就有水喝（自来水厂替你管）
```

## 二、依赖注入模式：Depends()

### 2.1 yield 是灵魂

```python
from sqlalchemy.orm import Session
from fastapi import Depends, FastAPI

def get_db():                          # 这就是一个"依赖"
    db = SessionLocal()                # ← 为被依赖者准备资源
    try:
        yield db                        # ← yield！不是一次性返回
        # ↑ yield 把 db 交给调用的路由函数使用
        # ↑ 路由函数执行完后，代码从 yield 下面继续
    finally:
        db.close()                      # ← 请求结束后自动关闭
        # ↑ 无论正常完成还是报错，finally 都会执行
```

**关键点：** yield 在依赖注入中的执行流程：

```
① get_db() 开始执行
       ↓
② db = SessionLocal()      → 创建数据库会话
       ↓
③ yield db                  → 暂停在这里，把 db 递给路由函数
       ↓                     → 路由函数拿到 db，开始干活（查数据/写数据）
       ↓
④ 路由函数执行完毕
       ↓
⑤ 代码回到 yield 下面继续 → 进入 finally 块
       ↓
⑥ db.close()               → 关闭数据库会话，释放资源
```

对比 return 和 yield 的区别：

```python
# ❌ 用 return —— 没有自动清理机制
def get_db_bad():
    db = SessionLocal()
    return db          # 返回后就没有地方自动关闭了
                         # 如果路由函数中报错了，db 永远关不掉！

# ✅ 用 yield + finally —— 保证清理
def get_db_good():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()     # 无论如何都会执行（正常结束/报错/取消）
```

### 2.2 在路由中使用

```python
from fastapi import FastAPI, Depends
from sqlalchemy.orm import Session

app = FastAPI()

@app.get("/todos")
def list_todos(db: Session = Depends(get_db)):   # ← FastAPI 自动调用 get_db()
    todos = db.query(Todo).all()
    return todos                                 # ← db 已经自动准备好了

@app.post("/todos", status_code=201)
def create_todo(todo: TodoCreate, db: Session = Depends(get_db)):
    new_todo = Todo(**todo.model_dump())         # Pydantic v2 用 model_dump()
    db.add(new_todo)
    db.commit()
    db.refresh(new_todo)
    return new_todo                              # ← db 同样自动可用
```

**发生了什么？**
1. FastAPI 看到 `db: Session = Depends(get_db)`，知道这是一个依赖
2. 在收到请求时，**自动调用** `get_db()`
3. `get_db()` 里的 `yield db` 把会话交给路由函数
4. 路由函数执行完毕后，`get_db()` 的 `finally` 块自动执行 → `db.close()`

## 三、数据库会话管理完整示例

这是整个集成的骨架，所有 CRUD 操作都建立在这个基础上：

```python
from fastapi import FastAPI, Depends, HTTPException, status
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, DeclarativeBase
from pydantic import BaseModel
from typing import Optional

# ===== 1. 数据库引擎 =====
DATABASE_URL = "sqlite:///./todos.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})

# ===== 2. Session 工厂 =====
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

# ===== 3. Base 基类 =====
class Base(DeclarativeBase):
    pass

# ===== 4. 依赖：每次请求获取独立 Session =====
def get_db():
    """FastAPI 依赖注入：自动管理 Session 生命周期"""
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# ===== 5. SQLAlchemy 模型（对应数据库表）=====
class Todo(Base):
    __tablename__ = "todos"

    id = Column(Integer, primary_key=True, index=True)
    title = Column(String, nullable=False)
    description = Column(String, nullable=True)
    category = Column(String, default="未分类")
    completed = Column(Boolean, default=False)

# ===== 6. 建表 =====
Base.metadata.create_all(bind=engine)

# ===== 7. Pydantic 模型（API 契约）=====
class TodoCreate(BaseModel):
    title: str
    description: Optional[str] = None
    category: str = "未分类"

class TodoUpdate(BaseModel):
    title: Optional[str] = None
    description: Optional[str] = None
    category: Optional[str] = None
    completed: Optional[bool] = None

class TodoResponse(BaseModel):
    id: int
    title: str
    description: Optional[str]
    category: str
    completed: bool
    class Config:
        from_attributes = True   # Pydantic v2 改为 from_attributes

# ===== 8. FastAPI 应用 =====
app = FastAPI(title="Todo API")

# ===== 9. CRUD 路由 =====
@app.get("/todos")
def list_todos(skip: int = 0, limit: int = 100, db: Session = Depends(get_db)):
    """列出所有待办（支持分页）"""
    return db.query(Todo).offset(skip).limit(limit).all()

@app.post("/todos", status_code=status.HTTP_201_CREATED)
def create_todo(todo: TodoCreate, db: Session = Depends(get_db)):
    """创建新待办"""
    db_todo = Todo(**todo.model_dump())
    db.add(db_todo)
    db.commit()
    db.refresh(db_todo)
    return db_todo

@app.get("/todos/{todo_id}")
def get_todo(todo_id: int, db: Session = Depends(get_db)):
    """获取单个待办详情"""
    todo = db.get(Todo, todo_id)
    if not todo:
        raise HTTPException(status_code=404, detail="待办不存在")
    return todo

@app.put("/todos/{todo_id}")
def update_todo(todo_id: int, todo: TodoUpdate, db: Session = Depends(get_db)):
    """全量更新待办"""
    db_todo = db.get(Todo, todo_id)
    if not db_todo:
        raise HTTPException(status_code=404, detail="待办不存在")
    for key, value in todo.model_dump().items():
        setattr(db_todo, key, value)
    db.commit()
    db.refresh(db_todo)
    return db_todo

@app.delete("/todos/{todo_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_todo(todo_id: int, db: Session = Depends(get_db)):
    """删除待办"""
    db_todo = db.get(Todo, todo_id)
    if not db_todo:
        raise HTTPException(status_code=404, detail="待办不存在")
    db.delete(db_todo)
    db.commit()
```

**整体结构拆解：**

| 部分 | 作用 | 几行代码 |
|------|------|---------|
| 引擎 + Session 工厂 | 数据库连接配置 | 2行 |
| get_db() | 依赖注入函数 | 5行 |
| SQLAlchemy 模型 | 定义表结构 | 7行 |
| Pydantic 模型 ×3 | 定义 API 请求/响应格式 | 15行 |
| CRUD 路由 ×5 | 具体的 API 接口 | 各 10行左右 |

## 四、Pydantic 模型 vs SQLAlchemy 模型

很多初学者搞混这两个，其实它们职责完全不同：

```
┌──────────────────────────────────────────────────┐
│           Pydantic 模型（API 层）                   │
│  职责：定义"谁"可以通过 API 传什么 / 返回什么         │
│  位置：在数据库外面                                   │
│  例子：客户端可以只传 title，description 可选         │
└──────────────┬──────────────────────┬────────────┘
               │ HTTP 请求/响应        │
               ▼                       ▼
┌──────────────────────────────────────────────────┐
│         SQLAlchemy 模型（数据库层）                  │
│  职责：定义"怎么"把数据存到数据库                    │
│  位置：直接操作数据库                               │
│  例子：表里有 id/title/description/category...     │
└──────────────────────────────────────────────────┘
```

**三个 Pydantic 模型分别负责：**

| 模型 | 用途 | 字段特点 |
|------|------|---------|
| `TodoCreate` | POST 创建时传什么 | 必填 + 可选，**不包含** id（数据库自增） |
| `TodoResponse` | GET 返回什么 | 包含 id + 所有可读字段 |
| `TodoUpdate` | PUT/PATCH 更新时传什么 | **全部可选**（PATCH 只需传要改的字段） |

**`from_attributes = True` 的作用：**

```python
class TodoResponse(BaseModel):
    id: int
    title: str
    class Config:
        from_attributes = True    # ← 告诉 Pydantic：可以从 ORM 对象读取属性

    # 默认情况下，Pydantic 期望的是字典。加上这个，就能直接接受 SQLAlchemy 对象。
```

## 五、事务管理

事务就是一组操作的"打包"：要么全部成功，要么全部失败回滚。

```python
def create_todo(todo: TodoCreate, db: Session = Depends(get_db)):
    try:
        db_todo = Todo(**todo.model_dump())
        db.add(db_todo)
        db.commit()                    # ← 提交：所有修改写入数据库
        db.refresh(db_todo)            # ← 刷新：获取自增的 id
        return db_todo
    except Exception as e:
        db.rollback()                  # ← 回滚：撤销刚才的所有操作
        raise HTTPException(
            status_code=500,
            detail=f"创建失败: {str(e)}"
        )
```

**commit / rollback / flush 的关系：**

| 方法 | 做了什么 | 能查到刚插入的数据吗？ |
|------|---------|---------------------|
| `db.flush()` | 同步到当前事务（还没写到磁盘） | 能（同一事务内） |
| `db.commit()` | 真正持久化到磁盘 + 结束事务 | 能（任何事务都能查到） |
| `db.rollback()` | 撤销当前事务的所有修改 | 不能（回退到 commit 前） |

**生活类比：**
- `flush()` = 写完作业放进书包（暂时保存，还能拿出来改）
- `commit()` = 把作业交给老师（正式提交，改不了了）
- `rollback()` = 后悔了，把作业要回来撕掉重做

## 六、依赖注入的高级用法

### 6.1 嵌套依赖

```python
def get_db():                           # 第一个依赖
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

def get_current_user(db: Session = Depends(get_db)) -> User:  # 第二个依赖依赖了第一个
    # FastAPI 会自动先调用 get_db()，再调用这个
    user = db.query(User).filter(User.id == 1).first()
    if not user:
        raise HTTPException(status_code=401, detail="未登录")
    return user

@app.post("/todos")
def create_todo(todo: TodoCreate, user: User = Depends(get_current_user), db: Session = Depends(get_db)):
    # db 和 user 都会被自动注入
    db_todo = Todo(**todo.model_dump(), user_id=user.id)
    ...
```

### 6.2 有缓存的依赖（同一个请求多次用到同一个 Session）

```python
# FastAPI 内部会自动处理——如果你在多个路由参数里用了同一个 Depends(get_db)，
# 它只会调用一次 get_db()，然后把同一个 db 传给所有需要的函数。
# 所以你不需要担心重复创建 Session 的问题。
```

## 七、常见错误排查

### 错误 1：忘记 yield，用了 return

```python
# ❌ 错误
def get_db():
    db = SessionLocal()
    return db          # 不会自动关闭！

# ✅ 正确
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### 错误 2：连接 SQLite 时报 "database is locked"

```python
# 解决方法：connect_args 加 check_same_thread
engine = create_engine(
    "sqlite:///./todos.db",
    connect_args={"check_same_thread": False}   # ← 加这行
)
```

### 错误 3：from_attributes 拼错

```python
# Pydantic v2 (最新)
class Config:
    from_attributes = True    # ← 注意是小写 under_score

# Pydantic v1（旧版）
class Config:
    orm_mode = True           # ← 这个是 v1 的写法
```

### 错误 4：model_dump() vs .dict()

```python
# Pydantic v2: model_dump()
data = todo.model_dump()

# Pydantic v1: .dict()
data = todo.dict()
```
