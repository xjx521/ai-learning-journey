## 一、为什么需要认证？

```
没有认证 → 任何人都能访问你的 API（危险！）
有认证 → 服务器验证"你是谁"才给数据
```

Web 应用最常见的流程：用户注册 → 用户登录 → 每次请求带身份证明。

### Session vs Token 对比

| 特性     | Session（传统方式）                                            | Token（JWT）                                             |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| 存储位置 | 服务器内存/数据库                                              | 客户端（浏览器 localStorage / 移动端 SharedPreferences） |
| 无状态   | ❌ 服务器要存 Session 数据                                      | ✅ 自包含一切信息，不需要查库                             |
| 水平扩展 | 难（多台服务器需要共享 Session，要用 Redis 或 sticky session） | 容易（每个请求都带着完整信息，哪台服务器都能验）         |
| 适合场景 | 单体应用、单机房部署                                           | 分布式/微服务/Mobile App/API 开放平台                    |
| 主动作废 | 简单（删 Session 即可）                                        | 麻烦（需要黑名单或改密钥来撤销）                         |

**类比：**
- Session 像酒店的房卡——酒店前台的电脑里记着"几号房配几号卡"，换一家酒店就失效了。
- JWT 像一个盖章的护照——任何人看到印章就能验证真假，不需要回政府查资料。

### 我们这一天的学习路径

```
用户注册 POST /register  → 密码用 bcrypt 哈希后存入数据库
    ↓
用户登录 POST /login    → 验证通过后签发 JWT（带用户 ID + 过期时间）
    ↓
后续请求                 → 在请求头带 Authorization: Bearer <token>
    ↓
服务器验证 JWT 签名      → 合法则放行，拿到用户信息；非法则返回 401
```

## 二、JWT 三大组成部分

JWT = JSON Web Token。它本质上是**一段 Base64Url 编码的字符串**，由三个部分组成，用 `.` 连接：

```
header.payload.signature
```

### 2.1 Header（头部）

记录使用的算法和 token 类型。

```jsonc
// 典型内容
{
  "alg": "HS256",   // 算法：HMAC with SHA-256
  "typ": "JWT"      // 类型：这是一个 JWT
}
```

然后做 Base64Url 编码（注意是 URL 安全的 Base64，不会把 `/` 变成 `+`，把 `=` 去掉）：

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
```

### 2.2 Payload（负载）

存放实际数据，这些数据叫 **claims（声明）**。常见字段：

| 预定义字段 | 含义                                | 示例值       |
| ---------- | ----------------------------------- | ------------ |
| `sub`      | subject（主题），通常是用户 ID      | `"123"`      |
| `name`     | 用户名                              | `"张三"`     |
| `iat`      | issued at（签发时间，Unix 时间戳）  | `1720000000` |
| `exp`      | expiration（过期时间，Unix 时间戳） | `1720086400` |
| `iss`      | issuer（签发者）                    | `"my-api"`   |

你也可以添加自定义字段，比如角色、权限等：

```jsonc
{
  "sub": "1",
  "username": "zhangsan",
  "role": "admin",
  "exp": 1720086400,
  "iat": 1720000000
}
```

Base64Url 编码后（这段很长）：

```
eyJzdWIiOiIxIiwidXNlcm5hbWUiOiJ6aGFuZ3NhbiIsInJvbGUiOiJhZG1pbiIsImV4cCI6MTcyMDA4NjQwMCwiaWF0IjoxNzIwMDAwMDAwfQ
```

### 2.3 Signature（签名）

这是 JWT **安全的核心**。签名的作用是告诉接收者："这段数据没有被篡改过"。

生成过程：

```python
import hmac
import hashlib

header_b64 = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"
payload_b64 = "eyJzdWIiOiIxIn0..."

# 把 header 和 payload 用 . 连起来
message = header_b64 + "." + payload_b64

# 用 HMAC-SHA256 算法 + 一个只有服务器知道的密钥做签名
secret = "super_secret_key_your_user_never_sees"  # ← 绝不应该泄露！
signature = hmac.new(
    secret.encode(),           # 密钥
    message.encode(),          # 要签名的消息
    hashlib.sha256             # 哈希算法
).hexdigest()
```

最终完整的 JWT 长这样（三段用 `.` 连接）：

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIn0.xK8v3mP9qL2nR5tY7wE1uA6sB4cD0fG3hJ5kM8oP2qS
        ───── Header ──────┬──────  ───── Payload ──────┬─────  ────── Signature ──────┬─────
```

### 2.4 完整工作流类比

```
发送方（服务器）：
1. 写信封 → Header（说明用什么方法加密）
2. 写内容  → Payload（用户信息）
3. 盖印章  → Signature（用只有我有钥匙的印章机按上去）
4. 寄出    → 整段 token 发给客户端

接收方（服务器收到请求时）：
1. 拆开信封 → 知道用 HS256 算法验证
2. 读内容  → 提取 user_id、role 等信息
3. 验印章  → 用同一把密钥重新算一遍签名，和收到的签名对比
   - 一样  → 没被篡改，信任这份数据
   - 不一样 → 被动了手脚，拒绝！
```

## 三、关键概念：哈希 vs 加密

很多人混淆这两个概念，但它们在安全中扮演完全不同的角色。

|              | 哈希（Hash）                       | 加密（Encrypt）            |
| ------------ | ---------------------------------- | -------------------------- |
| 方向         | 单向（不可逆）                     | 双向（可逆：加密→解密）    |
| 输入任意长度 | ✅ 输出固定长度                     | ✅ 输出密文                 |
| 相同输入     | ✅ 永远得到相同输出                 | ✅ 相同密钥下相同输出       |
| 能还原吗？   | **绝对不能**                       | 能（有密钥才行）           |
| 常用算法     | bcrypt、SHA-256、argon2            | AES、RSA                   |
| 我们的用途   | 存密码（即使数据库泄露也看不出来） | 传输敏感数据（如信用卡号） |

**⚠️ 重要：bcrypt 是哈希不是加密！** 你不能"解密" bcrypt 哈希值获得原始密码。你只能拿一个猜测的密码去"验证"它是否匹配。

```python
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
# CryptContext：passlib 库的统一加密管理工具，兼容几十种哈希加密算法。
# schemes=["bcrypt"]：指定使用 bcrypt 做密码哈希（后端最主流密码加密算法）。
# deprecated="auto"：自动标记废弃算法，算法过时会主动抛警告，保障安全

# 注册时：明文 → 哈希值（不可逆！）
hashed = pwd_context.hash("mypassword123")
print(hashed) 
# $2b$12$xK9...（很长一串随机字符）

# 登录时：验证猜测（不是解密！）
if pwd_context.verify("mypassword123", hashed):#verify(明文, 哈希)
    print("密码正确！")  # ✓ 验证通过
else:
    print("密码错误！")  # ✗ 验证失败
```

**为什么要用 bcrypt 而不是普通的 SHA-256？**

因为 bcrypt 有 **salting（加盐）** 和 **slow（慢）** 两个特性：

1. **加盐**：即使在数据库中两个用户的 bcrypt 哈希值看起来完全不同（即使用了相同的密码），攻击者也无法用一张彩虹表破解所有账户。
2. **慢**：bcrypt 故意设计得很慢（默认做了 12 轮迭代）。攻击者每秒能暴力破解普通哈希数十亿次，但对 bcrypt 每秒只能尝试几百次。

## 四、JWT 工作流程

```
① 用户打开登录页面，输入账号密码
         │
         ▼
② POST /auth/login → 把账号密码发到服务器
         │
         ▼
③ 服务器查数据库，找到该用户的记录
         │
         ▼
④ 用 pwd_context.verify(输入密码, 数据库中的哈希值) 验证
         │
     ┌───┴────┐
     │        │
   成功      失败
     │        │
     ▼        ▼
⑤ 签发 JWT  返回 401 {detail: "账号或密码错误"}
    （携带 sub、exp 等）
     │
     ▼
⑥ 返回给客户端 {"access_token": "eyJhbG...", "token_type": "bearer"}
     │
     ▼
⑦ 客户端保存 token（localStorage / sessionStorage / cookie）
     │
     ▼
⑧ 之后每次请求，在请求头带上：
   Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
     │
     ▼
⑨ 服务器收到请求：
   a) 从请求头提取 token
   b) 用 jwt.decode(token, SECRET_KEY, algorithms=["HS256"]) 验证
   c) 如果合法 → 取出 payload 中的用户信息 → 继续处理业务
   d) 如果过期（exp 已过）→ 抛出异常 → 返回 401
   e) 如果被篡改（签名不对）→ 抛出异常 → 返回 401
```

## 五、bcrypt 密码哈希详解

### 安装

```bash
pip install passlib[bcrypt]
```

### 基本用法

```python
from passlib.context import CryptContext

# 创建密码上下文对象
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# ===== 注册时：哈希密码 =====
plain_password = "my_secret_password"
hashed_password = pwd_context.hash(plain_password)
print(f"哈希结果：{hashed_password}")
# 输出类似：$2b$12$xK9pLmN3oQrStUvWxYzABCDEFghijklmnopqrstuv

# ===== 登录时：验证密码 =====
input_password = "my_secret_password"
if pwd_context.verify(input_password, hashed_password):
    print("✓ 密码正确，允许登录")
else:
    print("✗ 密码错误")

# 试一个错误的密码
if pwd_context.verify("wrong_password", hashed_password):
    print("密码正确")
else:
    print("✗ 密码错误")  # ← 会走到这里
```

### 破坏性实验：自己试试

1. 同一个密码两次 hash，结果一样吗？ → **不一样**（因为 bcrypt 每次自动生成不同的 salt）
2. 能从哈希值反推出原始密码吗？ → **不能**（这就是哈希的意义）
3. 如果我把哈希值存在前端 JS 代码里，还安全吗？ → **不安全！** 任何懂技术的人都能看到哈希值并用它伪造登录。哈希值只应该存在后端数据库里。

## 六、用 FastAPI 实现登录注册接口

### 整体架构

```
/users/register  (POST)  → 创建用户，密码哈希后入库
/auth/login      (POST)  → 验证密码，签发 JWT，返回 token
/protected       (GET)   → 需要 Bearer Token 才能访问的接口
```

### 依赖包

```bash
pip install fastapi uvicorn python-jose[cryptography] passlib[bcrypt]
```

### Step 1：基础配置 + 密码上下文

```python
from fastapi import FastAPI, HTTPException, Depends
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from pydantic import BaseModel
from jose import jwt, JWTError
from passlib.context import CryptContext
from datetime import datetime, timedelta, timezone

app = FastAPI(title="JWT 认证演示")

# 密钥 —— 生产环境应该从环境变量读取！
SECRET_KEY = "your-secret-key-change-in-production-abc123xyz"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30  # token 有效期 30 分钟

# 密码哈希上下文
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# OAuth2 Bearer Token 方案（FastAPI 内置）
# tokenUrl 指向登录接口，让 /docs 自动弹出授权按钮
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")
```

### Step 2：数据模型

```python
# 注册请求体
class UserRegister(BaseModel):
    username: str
    email: str
    password: str  # 明文密码，会被哈希后存储

# 登录请求体（OAuth2 标准格式）
# OAuth2PasswordRequestForm 会自动解析 form-data 类型的登录请求
class TokenResponse(BaseModel):
    access_token: str
    token_type: str

# 受保护接口的响应
class ProtectedResponse(BaseModel):
    message: str
    username: str
```

### Step 3：模拟数据库（先用内存字典，后面替换为 SQLAlchemy）

```python
# 模拟数据库：key=用户名，value=数据库记录
fake_db: dict[str, dict] = {}

def get_user_from_db(username: str) -> dict | None:
    """根据用户名查用户"""
    return fake_db.get(username)
```

### Step 4：POST /register 注册接口

```python
@app.post("/users/register", status_code=201)
def register(user: UserRegister):
    # 1. 检查用户名是否已存在
    if user.username in fake_db:
        raise HTTPException(status_code=400, detail="用户名已被注册")

    # 2. 哈希密码
    hashed = pwd_context.hash(user.password)

    # 3. 存入"数据库"（真实场景中用 SQLAlchemy 插入 users 表）
    fake_db[user.username] = {
        "username": user.username,
        "email": user.email,
        "hashed_password": hashed,
    }

    return {"message": f"用户 {user.username} 注册成功！"}
```

### Step 5：POST /auth/login 登录接口

```python
@app.post("/auth/login", response_model=TokenResponse)
def login(form_data: OAuth2PasswordRequestForm = Depends()):
    # 1. 查用户
    db_user = get_user_from_db(form_data.username)
    if not db_user:
        raise HTTPException(status_code=401, detail="账号或密码错误")

    # 2. 验证密码（用 verify 对比，不能用 == 直接比较！）
    if not pwd_context.verify(form_data.password, db_user["hashed_password"]):
        raise HTTPException(status_code=401, detail="账号或密码错误")

    # 3. 签发 JWT Token
    #    设置过期时间：当前时间 + 30 分钟
    expire = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    
    #    payload 内容（只有这些会被存到 token 里）
    payload = {
        "sub": db_user["username"],      # 主题：用户名
        "exp": expire,                    # 过期时间
        "iat": datetime.now(timezone.utc), # 签发时间
    }

    #    生成 token（内部做了 header 编码 + payload 编码 + signature 签名）
    token = jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

    return TokenResponse(access_token=token, token_type="bearer")
```

### Step 6：Bearer Token 验证函数

```python
def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    """
    从 Bearer Token 中提取用户信息
    
    这个函数会在每个需要认证的接口中被自动调用（Depends(get_current_user)）
    """
    credentials_exception = HTTPException(
        status_code=401,
        detail="无法验证凭证",
        headers={"WWW-Authenticate": "Bearer"},  # 告诉客户端需要用 Bearer 格式
    )

    try:
        # 解码并验证 token
        #    - SECRET_KEY：必须是和签发时用的一样的密钥
        #    - algorithms：必须包含签发时用的算法
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str | None = payload.get("sub")
        
        if username is None:
            raise credentials_exception

    except JWTError:
        # token 签名不对、格式错误或过期都会到这里
        raise credentials_exception

    # 查"数据库"获取完整用户信息
    user = get_user_from_db(username)
    if user is None:
        raise credentials_exception

    return user
```

### Step 7：需要认证的接口

```python
@app.get("/protected", response_model=ProtectedResponse)
def protected_route(current_user: dict = Depends(get_current_user)):
    return ProtectedResponse(
        message="恭喜你！你已经通过了 JWT 认证！",
        username=current_user["username"],
    )

@app.get("/")
def index():
    return {"message": "欢迎！这个接口不需要认证。"}
```

### 测试流程

1. 启动：`uvicorn main:app --reload`
2. 打开 http://localhost:8000/docs 看 Swagger UI
3. 依次测试：
   - GET / （不需要认证，直接成功）
   - POST /users/register → 注册一个新用户
   - POST /auth/login → 登录拿到 token
   - 点页面上方的 "Authorize" 按钮，粘贴 token
   - GET /protected → 认证成功，显示欢迎信息
   - 不贴 token 直接调 /protected → 401 Unauthorized

## 七、Security 最佳实践

### 7.1 密钥管理

```python
# ❌ 错误：硬编码在代码里
SECRET_KEY = "my-secret-key"

# ✅ 正确：从环境变量读取
import os
SECRET_KEY = os.environ["JWT_SECRET_KEY"]
```

### 7.2 Token 有效期不宜过长

```python
# 登录接口：短有效期（30 分钟），频繁刷新
ACCESS_TOKEN_EXPIRE_MINUTES = 30

# 如果需要"记住我"功能，可以用 refresh token（7-30 天）
# refresh token 单独存在数据库里，到期后让用户重新登录
```

### 7.3 生产环境还要考虑

| 安全措施        | 说明                                                  |
| --------------- | ----------------------------------------------------- |
| HTTPS           | 防止中间人窃取 token                                  |
| HttpOnly Cookie | 不让 JavaScript 读到 token，防 XSS 攻击               |
| CSRF Token      | 防止跨站请求伪造                                      |
| Token 黑名单    | 用户登出后把 token 加入黑名单（短期有效的话可以忽略） |
| Rate Limiting   | 登录接口限制频率，防暴力破解                          |
