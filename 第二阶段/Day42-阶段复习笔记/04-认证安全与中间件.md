# 第 11 章 JWT 认证基础(Day33)

## 11.1 为什么需要认证:Session vs Token

### 🔴 HTTP 无状态 → 每次请求都要"证明你是谁"

> 📌 **知识点说明**:HTTP 是无状态的(服务器不记得上一个请求是谁发的)。所以每次请求要带"身份凭证"。
>
> 类比:进健身房,每次都要刷会员卡(凭证)。Session = 健身房发一张**实体卡号,前台看后台系统核验**;Token(JWT)= 健身房给你一张**盖了章的卡,前台认章不认人**。

| 对比 | Session(会话) | Token(JWT) |
|------|--------------|-----------|
| 凭证存在哪 | 服务器内存/数据库(有状态) | 客户端本地(无状态) |
| 服务器要记吗 | 要,记住了才能认你 | 不用记,验证签名即可 |
| 分布式扩展 | 难(会话数据要共享) | 容易(任何服务器都能验) |
| 注销/踢人 | 方便(删掉服务器记录) | 麻烦(要让 token 失效) |
| 常用场景 | 传统 Web 应用 | API / 前后端分离 / 移动端 |

💡 **速记**:Session 靠"记得你",JWT 靠"证明是你"。**API 开发首选 JWT**。

## 11.2 JWT 结构:三段式

### 🔴 Header.Payload.Signature

> 📌 **知识点说明**:JWT = 三个部分用 `.` 拼起来:**Header(头,声明算法)→ Payload(载荷,放身份信息)→ Signature(签名,防篡改)**。前两段是 Base64 编码的 JSON,**任何人都能解码看内容,所以别放密码等敏感信息**。

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ4angifQ.fooBarSignature
└─────Header──────┘ └─────Payload─────┘ └────Signature────┘
   {"alg":"HS256"}      {"sub":"xjx"}
```

| 段 | 内容 | 例子 | 能解密吗 |
|----|------|------|---------|
| Header | 算法类型 | `{"alg":"HS256","typ":"JWT"}` | 是(Base64) |
| Payload | 用户信息 + 过期时间 | `{"sub":"1","exp":1780000000}` | 是(Base64) |
| Signature | 前两段 + 密钥哈希出来的签名 | `HMACSHA256(...)` | 需要密钥 |

💡 **核心理解**:Payload 可以随便看(public),但**改一个字,签名就对不上**,服务器验签直接拒绝 → 保证**完整性**(没被篡改)。

## 11.3 签发令牌:jwt.encode

### 🔴 签发 + 过期时间

> 📌 **知识点说明**:用 `jwt.encode(payload, secret, algorithm="HS256")` 签发。**Secret(密钥)是签名的"私章",必须放环境变量,绝不放代码里**。`exp` 控制过期时间(用 `datetime.timedelta` 算未来的时间戳)。

```python
import jwt
from datetime import datetime, timedelta

SECRET_KEY = "your-secret-key"        # ⚠️ 生产必须从环境变量读,不能写死在代码!
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30       # 令牌 30 分钟过期

def create_access_token(user_id: int):
    # 1. 准备 payload(身份信息)
    payload = {
        "sub": str(user_id),           # sub = 用户 ID(约定俗称的字段)
        "exp": datetime.utcnow() + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES),  # 过期时间
    }
    # 2. 编码签发:用密钥 + 算法给 payload 加签名
    token = jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)
    return token
```

## 11.4 验证令牌:jwt.decode

### 🔴 验签 + 取用户身份

> 📌 **知识点说明**:`jwt.decode(token, secret, algorithms=[...])` 验证签名并取回 payload。**签名对不上或已过期会抛异常**(`InvalidTokenError` / `ExpiredSignatureError`),要捕获后返回 401。

```python
def get_user_from_token(token: str):
    try:
        # 验签:签名错误/密钥不对/过期都会抛异常
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return int(payload["sub"])     # 取出用户 ID
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="令牌已过期,请重新登录")
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail="无效的令牌")
```

⚠️ **易错点**:
```python
# ❌ algorithms 不指定或写错 → 可能被算法混淆攻击 / 报错
# jwt.decode(token, SECRET_KEY)
# ✅ 必须显式指定
jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
```

## 11.5 OAuth2PasswordBearer:让 FastAPI 收 Token

### 🔴 告诉 FastAPI "Token 放在哪"

> 📌 **知识点说明**:`OAuth2PasswordBearer(tokenUrl="login")` 是 FastAPI 的"取令牌器"——告诉框架 **Token 通过 Authorization 请求头传**。当某个接口需要认证时,它会自动解析请求头里的 Bearer Token,没有就返回 401。

```python
from fastapi.security import OAuth2PasswordBearer

# 声明:Token 从 Authorization 请求头取,格式是 "Bearer <token>"
# tokenUrl 只是文档里提示"去哪登录",不真的调
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")

@app.get("/users/me")
async def read_users_me(token: str = Depends(oauth2_scheme)):
    # 路由里声明 Depends(oauth2_scheme) → FastAPI 自动取出 Token 放进 token
    user = get_user_from_token(token)
    return {"current_user": user}
```

## 11.6 OAuth2PasswordRequestForm:登录表单

### 🔴 接收用户名密码的表单

> 📌 **知识点说明**:`OAuth2PasswordRequestForm` 专门解析**登录表单**(form-urlencoded 格式,不是 JSON),字段固定是 `username` + `password`。注意登录接口**不能声明为 JSON 请求体**,必须用 Form 依赖。

```python
from fastapi.security import OAuth2PasswordRequestForm
from fastapi import Depends, HTTPException

@app.post("/login")
async def login(form_data: OAuth2PasswordRequestForm = Depends()):
    # 1. 校验用户名密码(生产要查数据库 + bcrypt 比对)
    if form_data.username != "xjx" or form_data.password != "123456":
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    # 2. 签发令牌
    token = create_access_token(user_id=1)
    return {"access_token": token, "token_type": "bearer"}
```

| 对比 | JSON 请求体 | OAuth2PasswordRequestForm |
|------|------------|--------------------------|
| 格式 | application/json | application/x-www-form-urlencoded |
| 写法 | `def login(data: LoginIn)` | `def login(form_data: OAuth2PasswordRequestForm = Depends())` |
| 场景 | 自定义接口 | 配合 OAuth2 文档的登录 |

## 11.7 权限控制:get_current_user 依赖

### 🔴 把"验 Token"变成"可复用的依赖"

> 📌 **知识点说明**:把"取 Token → 解 Token → 查用户"打包成一个依赖 `get_current_user`。**任何路由只要写 `user: User = Depends(get_current_user)`,就自动完成鉴权**,没登录直接 401,登录了把用户对象传给路由。

```python
from typing import Annotated

def get_current_user(token: str = Depends(oauth2_scheme)):
    # 1. 验签失败 → 401
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        user_id = payload.get("sub")
    except jwt.PyJWTError:
        raise HTTPException(status_code=401, detail="无效的认证凭证")
    # 2. 查用户(生产从数据库查)
    user = fake_users_db.get(user_id)
    if user is None:
        raise HTTPException(status_code=401, detail="用户不存在")
    return user

# 用法:路由参数加 Depends(get_current_user)
@app.get("/todos/me")
async def my_todos(current_user: Annotated[User, Depends(get_current_user)]):
    return {"你已登录": current_user.username}
```

## 11.8 密码哈希:bcrypt

### 🟡 密码绝不能明文存

> 📌 **知识点说明**:存密码必须**哈希**(单向函数,只进不出)。登录时把输入的密码重新哈希,和库里存的对不对得上。**bcrypt 是专门给密码设计的慢哈希**(自带盐 salt,防彩虹表)。库:passlib + bcrypt。

```python
from passlib.context import CryptContext

# 声明用 bcrypt 算法(可切换,统一入口)
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 注册:哈希后入库
hashed_password = pwd_context.hash("123456")
# $2b$12$xxxxxxxx...   ← 每次结果都不同(内含随机盐),这是正常的!

# 登录:校验(能匹配 true 否则 false)
is_correct = pwd_context.verify("123456", hashed_password)
```

⚠️ **易错点**:
```python
# ❌ 明文存密码 / 用 MD5 等快哈希(可被秒破)
# db_password = "123456"
# ✅ bcrypt 哈希存储
# hashed_password = pwd_context.hash("123456")
```

| 对比 | 哈希(Hash) | 加密(Encryption) |
|------|-----------|-----------------|
| 方向 | 单向,不可逆 | 双向,可解密 |
| 目的 | 存密码/校验完整性 | 传输保密 |
| 例子 | bcrypt、SHA-256 | AES、RSA |

# 第 12 章 中间件 + 错误处理 + 环境变量(Day34)

## 12.1 中间件执行流程(洋葱模型)

### 🔴 Request 进来 → 中间件 → 路由 → 中间件 → Response 出去

> 📌 **知识点说明**:中间件 = 请求进出的"必经安检站"。**每个请求都要穿过中间件**,可以在进去前做检查(认证、日志、CORS),在回来时做收尾(记录耗时、统一包装)。
>
> 类比:快递进小区,门卫先检查(进),出来时再看看有没有违规(出)。

```
请求进来(最外层)
  → 中间件A(进,on_request)
    → 中间件B(进,on_request)
      → 路由函数(业务处理)
      → 中间件B(出,on_response)
    → 中间件A(出,on_response)
响应出去(最外层)
```

⚠️ **易错点**:**
**add_middleware 后注册的先执行**(先进后出,洋葱最外层):
```python
app.add_middleware(LoggingMiddleware)  # 后注册 → 先执行(最外层)
app.add_middleware(CORSMiddleware)     # 先注册 → 后执行(内层)
# 实际执行顺序:Logging → CORS → 路由 → CORS → Logging
```

## 12.2 CORS 跨域

### 🔴 什么是跨域 + 怎么解决

> 📌 **知识点说明**:浏览器安全策略(同源):协议 + 域名 + 端口 三者一致才叫同源。**前端(如 Streamlit 8501 端口)调后端(8000 端口)= 跨域 → 浏览器拦截响应**。后端用 `CORSMiddleware` 告诉浏览器"允许哪些来源访问我"。

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:8501"],  # 允许哪个前端来源
    allow_credentials=True,    # 允许携带 Cookie/凭证
    allow_methods=["*"],       # 允许的 HTTP 方法(全部)
    allow_headers=["*"],       # 允许的请求头(全部)
)
```

| CORS 配置项 | 作用 |
|------------|------|
| allow_origins | 允许的前端地址列表(跨域的核心) |
| allow_methods | 允许的方法(GET/POST/...) |
| allow_headers | 允许的请求头 |
| allow_credentials | 是否允许带 Cookie/Authorization |
| expose_headers | 允许前端读取的响应头 |

💡 **速记**:CORS 是**后端开的门**,不是前端能解决的问题。

⚠️ **易错点**:**宽松 CORS(allow_origins=["*"]) + allow_credentials=True 会报错**(浏览器不允许)。要么指定具体来源,要么去掉 credentials。
```python
# ❌ 报错:不能同时用 * 和 credentials
# allow_origins=["*"], allow_credentials=True
# ✅ 方案一:指定具体来源
allow_origins=["http://localhost:8501"], allow_credentials=True
# ✅ 方案二:放开所有但不带凭证
allow_origins=["*"], allow_credentials=False
```

## 12.3 自定义中间件:BaseHTTPMiddleware

### 🟡 记录日志 + 耗时

> 📌 **知识点说明**:用 `BaseHTTPMiddleware` 写自己的中间件。核心方法是 `dispatch(request, call_next)`:`call_next(request)` 把请求**传给下一层**(路由),拿到响应后可以继续加工。

```python
from starlette.middleware.base import BaseHTTPMiddleware
import time, logging

logging.basicConfig(level=logging.INFO)

class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        start = time.time()                                # 进去前记时间
        # 请求进来:记录是谁调的
        logging.info(f"收到请求: {request.method} {request.url.path}")
        response = await call_next(request)                # ← 传给下一层(路由)
        # 响应回来:算耗时
        cost = time.time() - start
        logging.info(f"请求完成: {response.status_code}, 耗时 {cost:.2f}s")
        return response                                    # 返回给上一层

app.add_middleware(LoggingMiddleware)
```

## 12.4 全局异常处理:统一错误格式

### 🔴 所有错误都返回一个格式

> 📌 **知识点说明**:用 `@app.exception_handler(类型)` 注册全局异常处理器,**把不同类型的错误(参数校验错 422 / HTTPException 4xx / 服务器内部错 500)统一成同一种 JSON 格式**,前端只需检查 `success` 一个字段。

```python
from fastapi.exceptions import RequestValidationError
from fastapi import HTTPException, Request
from fastapi.responses import JSONResponse

# 统一响应格式:success + message + data
def error_response(status: int, message: str, data=None):
    return JSONResponse(
        status_code=status,
        content={"success": False, "message": message, "data": data},
    )

# ① 参数校验错误(Pydantic 自动抛 422)
@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return error_response(422, f"参数格式错误: {exc.errors()}")

# ② 主动抛出的 HTTPException(业务错误 404/401/403...)
@app.exception_handler(HTTPException)
async def http_exception_handler(request: Request, exc: HTTPException):
    return error_response(exc.status_code, str(exc.detail))

# ③ 兜底:没被上面接住的异常(服务器内部错误 500)
@app.exception_handler(Exception)
async def generic_exception_handler(request: Request, exc: Exception):
    return error_response(500, f"服务器内部错误: {str(exc)}")
```

| 错误类型 | 谁来抛 | 状态码 |
|---------|--------|--------|
| RequestValidationError | Pydantic 自动(类型/校验不符) | 422 |
| HTTPException | 你主动 `raise`(业务错误) | 4xx 任意 |
| 未捕获异常 | 代码 bug | 500 |

## 12.5 环境变量:python-dotenv

### 🔴 密钥/配置别写死代码

> 📌 **知识点说明**:数据库密码、SECRET_KEY、Debug 开关等**环境相关的配置放 `.env` 文件**,用 `python-dotenv` 加载。`.env` 要加进 `.gitignore`(**绝不提交到 GitHub**,否则密钥泄露)。

```bash
# .env 文件(不要提交 git!)
DATABASE_URL=mysql+pymysql://root:123456@localhost:3306/ai_app
SECRET_KEY=my-super-secret-key
DEBUG=true
ALLOWED_ORIGINS=http://localhost:8501,http://localhost:3000
```

```python
import os
from dotenv import load_dotenv

load_dotenv()                      # 把 .env 里的变量加载进环境

DATABASE_URL = os.getenv("DATABASE_URL")                # 拿不到返回 None
SECRET_KEY = os.getenv("SECRET_KEY", "dev-secret")      # 带默认值(本地开发)
DEBUG = os.getenv("DEBUG", "false").lower() == "true"   # 字符串 "true" → 布尔 True

# 列表类型:逗号分隔字符串 → 列表
ALLOWED_ORIGINS = os.getenv("ALLOWED_ORIGINS", "").split(",")
# ['http://localhost:8501', 'http://localhost:3000']
```

⚠️ **易错点**:
```python
# ❌ DEBUG = os.getenv("DEBUG")  → 得到字符串 "true",if DEBUG 永远成立
# ✅ 必须转布尔:把字符串 "true" 转成 True
DEBUG = os.getenv("DEBUG", "false").lower() == "true"
```

| 多环境 | 文件 | 用途 |
|--------|------|------|
| 本地开发 | `.env.development` | 本地数据库、DEBUG=true |
| 生产部署 | `.env.production` | 线上数据库、DEBUG=false |
| 加载 | `load_dotenv(".env.development")` | 按需加载对应文件 |

# 第 13 章 综合项目:Todo API 用户系统(Day35)

## 13.1 项目架构总览

### 🔴 把前几章串起来:认证 + 业务 + 权限

> 📌 **知识点说明**:Day35 给 Day28 的待办 API 加完整用户系统:**每个待办属于一个用户,只有登录的用户能操作自己的待办**。这相当于"给 API 装上门禁"——没登录进不来,别人的房间进不去。

```
功能清单:
① 注册 POST /auth/register   → 用户名 + 密码(bcrypt 哈希存库)
② 登录 POST /auth/login      → 校验密码 → 返回 JWT
③ 鉴权(依赖) get_current_user → 解 Token → 查用户 → 注入路由
④ 业务路由全部带鉴权 + 权限控制(只能改删自己的待办)
⑤ CORS 从环境变量读 + 数据表关联(user_id 外键)
```

## 13.2 模型层:User + Todo 关联

### 🔴 一个用户多个待办(一对多)

> 📌 **知识点说明**:User 表 + Todo 表,`Todo.user_id` 外键指向 User。Todo 存 `user_id`,查询时按它过滤 → 天然做到"每个用户只能看到自己的待办"。

```python
from sqlalchemy import Column, Integer, String, Boolean, ForeignKey
from sqlalchemy.orm import relationship, declarative_base

Base = declarative_base()

class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String, unique=True, nullable=False)   # 用户名唯一
    hashed_password = Column(String, nullable=False)          # 存哈希不存明文
    todos = relationship("Todo", back_populates="owner",
                         cascade="all, delete-orphan")        # 删用户删他的待办

class Todo(Base):
    __tablename__ = "todos"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String, nullable=False)
    completed = Column(Boolean, default=False)
    user_id = Column(Integer, ForeignKey("users.id"))          # 外键:属于哪个用户
    owner = relationship("User", back_populates="todos")       # 反向关系
```

## 13.3 注册 / 登录路由

### 🔴 密码哈希入库 + JWT 签发

> 📌 **知识点说明**:注册 = 用户名查重 + bcrypt 哈希 + 入库;登录 = 查用户 + verify 密码 + 签发 token。**两个核心安全点:密码永远只存哈希;token 只在登录成功时签发。**

```python
from passlib.context import CryptContext
from sqlalchemy.orm import Session
from fastapi import Depends, HTTPException, status

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# ---- 注册 ----
@app.post("/auth/register", status_code=201)
def register(username: str, password: str, db: Session = Depends(get_db)):
    # 1. 查重
    existing = db.query(User).filter(User.username == username).first()
    if existing:
        raise HTTPException(status_code=400, detail="用户名已被注册")
    # 2. 哈希密码
    hashed = pwd_context.hash(password)
    # 3. 入库
    user = User(username=username, hashed_password=hashed)
    db.add(user)
    db.commit()
    db.refresh(user)
    return {"msg": "注册成功", "user_id": user.id}

# ---- 登录 ----
@app.post("/auth/login")
def login(form_data: OAuth2PasswordRequestForm = Depends(), db: Session = Depends(get_db)):
    # 1. 查用户
    user = db.query(User).filter(User.username == form_data.username).first()
    # 2. 密码校验(verify 而不是直接比字符串)
    if not user or not pwd_context.verify(form_data.password, user.hashed_password):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    # 3. 签发 token
    token = create_access_token(user_id=user.id)
    return {"access_token": token, "token_type": "bearer"}
```

## 13.4 鉴权依赖:get_current_user

### 🔴 所有需要登录的路由共享它

> 📌 **知识点说明**:一个依赖搞定"登录检查 + 取用户",业务路由只要声明依赖就自动受保护。

```python
from fastapi.security import OAuth2PasswordBearer
import jwt

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="auth/login")

def get_current_user(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)):
    # 1. 解 Token(过期/伪造 → 401)
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        user_id = payload.get("sub")
    except jwt.PyJWTError:
        raise HTTPException(status_code=401, detail="无效的认证凭证")
    # 2. 查用户
    user = db.query(User).filter(User.id == user_id).first()
    if user is None:
        raise HTTPException(status_code=401, detail="用户不存在")
    return user
```

## 13.5 业务路由 + 权限控制

### 🔴 只能操作自己的数据(重点!)

> 📌 **知识点说明**:创建待办绑定 `user_id`;**更新/删除前校验 `todo.user_id == current_user.id`,不是自己的就 403**。这是"权限控制/数据隔离"的标准写法,面试必问。

```python
# ---- 创建:自动绑定当前登录用户 ----
@app.post("/todos", status_code=201)
def create_todo(todo: TodoCreate, db: Session = Depends(get_db),
                current_user: User = Depends(get_current_user)):
    new_todo = Todo(**todo.model_dump(), user_id=current_user.id)  # 绑上登录用户
    db.add(new_todo)
    db.commit()
    db.refresh(new_todo)
    return new_todo

# ---- 更新:只能改自己的 ----
@app.put("/todos/{todo_id}")
def update_todo(todo_id: int, todo: TodoUpdate, db: Session = Depends(get_db),
                current_user: User = Depends(get_current_user)):
    item = db.query(Todo).filter(Todo.id == todo_id).first()
    if not item:
        raise HTTPException(status_code=404, detail="待办不存在")
    # ⭐ 权限检查:不是自己的 → 403(越权访问)
    if item.user_id != current_user.id:
        raise HTTPException(status_code=403, detail="无权修改他人的待办")
    item.title = todo.title
    db.commit()
    return item

# ---- 我的待办列表:按当前用户过滤 ----
@app.get("/todos/me")
def my_todos(db: Session = Depends(get_db), current_user: User = Depends(get_current_user)):
    return db.query(Todo).filter(Todo.user_id == current_user.id).all()
```

## 第 13 章【错误原因 + 修复方案】模块

### ❌ 问题 1:Day33 登录接口返回 token_type 而非 access_token

**错误原因**:课程实验要求简化,返回字段名写错;前端/标准 OAuth2 客户端期望的是 `access_token` + `token_type`。

**修复方案**:
```python
# ❌ 返回错字段名
# return {"token_type": token, "type": "bearer"}
# ✅ 标准字段名(前端取 res.access_token)
return {"access_token": token, "token_type": "bearer"}
```

### ❌ 问题 2:Day33 密码哈希未真正实现

**错误原因**:登录实验直接拿明文比对(`form_data.password == "123456"`),一旦接数据库就会泄露明文密码。

**修复方案**:用 passlib 实现哈希(见 13.3)——存 `pwd_context.hash()`,验 `pwd_context.verify()`。Day35 已正式解决。

### ❌ 问题 3:宽松 CORS + allow_credentials 冲突

**错误原因**:`allow_origins=["*"]` 和 `allow_credentials=True` 同时用,浏览器拒绝。

**修复方案**:指定具体来源列表,或去掉 credentials(见 12.2)。

### ❌ 问题 4:越权漏洞(没校验 user_id)

**错误原因**:更新/删除接口只查了 `todo_id`,没验证"这条待办是不是当前登录用户的" → 任意用户能改删别人的数据。

**修复方案**:加权限检查 `if item.user_id != current_user.id: raise 403`(见 13.5)。
